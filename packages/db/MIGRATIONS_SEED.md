# TASK-05 — SQL guards, QA seed и репетиция миграций

Поздний инкремент TASK-07 добавляет третью миграцию Identity и три модели (всего 66).
Ниже зафиксирован результат TASK-05; текущая цепочка и recovery описаны в
[Identity](../../apps/api/IDENTITY.md). Команды миграций автоматически применяют новую миграцию.

Проверено 26 октября 2026 на локальной PostgreSQL 18.6. Активная цепочка:
`20261026020000_init` → `20261026030000_task05_guards`. Применённая init не изменялась;
тот же добавочный SQL включён в `migrations-history` для прежней цепочки TASK-02/03/04.

## SQL

- `btree_gist` и `no_overlapping_confirmed_lessons`: один преподаватель не может иметь
  пересекающиеся `tstzrange(scheduled_at, scheduled_end_at, '[)')` для любого статуса,
  кроме CANCELLED. Имена физических полей — `scheduled_teacher_id`, `scheduled_at`,
  `scheduled_end_at`. Смежные интервалы разрешены.
- `uq_payment_distribution_unique(payment_id, subscription_id)` защищает пару
  платёж/абонемент; `payment_id` — фактическое имя FK к PaymentReceipt.
- `check_ledger_balance` вызывается при публикации, считает знаковые суммы отдельно
  по каждой валюте и запрещает пустую проводку. Черновик собирается построчно.
  Прежние проверки положительных сумм, точного balance_snapshot и блокировка родителя
  проводки сохраняются. В NestJS действует такая же проверка всех строк по валютам.
- Опубликованные entry/lines защищены существующими триггерами и runtime RLS.
  Вместо `DO INSTEAD NOTHING` для владельца БД возвращается явная ошибка;
  runtime не может обновить опубликованные строки.
- `t03_require_open_period` блокирует период и отклоняет финансовую запись в закрытом
  периоде. Для consumption проверяется дата самого урока. Межтабличное условие
  реализовано триггером, поскольку PostgreSQL CHECK не предназначен для такой проверки.
  NestJS сохраняет CLOSED_PERIOD denial в отдельной транзакции; успешная операция
  по-прежнему сохраняет audit/outbox вместе с финансовыми изменениями.

Отказ прямого SQL внутри отменённой транзакции не может сохранить audit в той же
транзакции. Для запросов приложения отказ сохраняется отдельно; аудит SQL-доступа
администратора относится к конфигурации эксплуатации.

## Команды и явные адреса

Значения задаются через окружение или локальный `packages/db/.env`, который игнорируется.
Примеры без действительных секретов находятся в `.env.example`.

| Команда из корня                                    | Переменная                    | Поведение                                                                                                                                                  |
| --------------------------------------------------- | ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm db:migrate:dry-run`                           | `MIGRATION_TEST_DATABASE_URL` | Требует пустую PostgreSQL 18; применяет миграции, проверяет status и schema diff. Это реальная репетиция на отдельной БД.                                  |
| `pnpm db:migrate:up`                                | `STAGING_DATABASE_URL`        | Проверяет историю/checksums, прежние пересечения календаря и дубли распределений; выбирает current/legacy chain, deploy, status, diff.                     |
| `pnpm db:seed`                                      | `QA_DATABASE_URL`             | Синтетический QA-набор, без удаления и сброса.                                                                                                             |
| `pnpm db:reset-qa`                                  | `QA_DATABASE_URL`             | Отдельный `prisma migrate reset --force`; удаляет данные только в явно названной локальной QA-БД, затем применяет миграции; seed нужно запускать отдельно. |
| `pnpm --filter @online-school/db db:seed:reference` | `DIRECT_URL`                  | Только пять ролей, без аккаунтов и финансовых fixtures; также вызывается через `prisma db seed`.                                                           |

Staging не подставляется из runtime/DIRECT_URL. Перед deploy нет автоматического
удаления конфликтующих записей. При `APP_ENV=production` QA/staging инструменты
отказывают. Сброс разрешён только для localhost/127.0.0.1/::1 и имени
`online_school_qa*` либо `online_school_test_qa*`. Remote QA seed требует одновременно
явных `QA_DATABASE_URL` и `APP_ENV=qa`; remote reset запрещён.

## Синтетические fixtures

`seed.ts` компилируется строгим TypeScript в `dist-tools/seed.js`. Метки
`seed-director-001`, `seed-manager-001/002`, `seed-teacher-001/002`,
`seed-student-001/002/003` детерминированно преобразуются в UUIDv5, поскольку PK
проекта — PostgreSQL UUID. Seed использует одну транзакцию и advisory lock.
Существующие записи не перезаписываются: сохраняются ID, timestamps и история.

Создаются директор, два менеджера, два преподавателя, три Student, математика,
три enrollment, одно назначение и recurring slot, уроки SCHEDULED/CONDUCTED/CANCELLED,
один Subscription, подтверждённый директором платёж/распределение, Grant на два урока,
одно Consumption и сбалансированная опубликованная проводка на 100 MDL.
Audit и pending-outbox имеют явную синтетическую тему `qa.fixture.ledger.v1`.

StudentAccount создаётся только для первого, оплаченного ученика; остальные двое
остаются реестровыми Student без кабинета. Логины используют `.invalid`, паролей нет.
Три staff WebAuthn-заглушки содержат заведомо неверный COSE public key и сразу отозваны.
Они не дают рабочего входа или MFA.

## Доказательства и границы

На чистой БД прошли обе миграции, `migrate status` и `migrate diff --exit-code`.
Локальный staging сначала получил точную прежнюю init и QA-данные, затем новую миграцию;
SHA-256 снимка всех прикладных строк вместе с timestamps до/после совпал.
Реальный внешний staging не указан и этой проверкой не подтверждён.

Шесть тестов `test/qa/seed-guards.test.mjs` проверили повторный/конкурентный seed без
изменения данных, exclusion (включая STAR_PENDING/DISPUTED и смежность), уникальность,
immutability, независимый incremental balance trigger, guards инструментов и
отдельный audit отказа закрытого периода. Последний тест закрывает QA-период;
для повторения всего набора предназначена отдельная одноразовая QA-БД.

```sh
pnpm --filter @online-school/db test:qa
```

Проверку реального `db:reset-qa` остановила встроенная защита Prisma для AI-агентов:
она требует отдельного явного согласия на уничтожение всех QA-данных. Данные не удалены,
защита не обходилась. Применение миграций и seed проверены независимо от reset.
