# K8K Academy — айдентика кабинетов

Каноническая визуальная опора, утверждённая прямыми запросами владельца 08.11.2026:
`template/newtemp.png`, `template/schedule.png`, `template/homework.png`,
`template/путьзнаний.png`. Новые страницы должны продолжать эту систему.
Документ управляет оформлением, а бизнес-правила остаются в требованиях `docs/`.
Название продукта — K8K Academy; вариант K&K на сгенерированных макетах не является
решением о переименовании.

## Визуальный характер

Тёмная морская навигация, светлый тёплый фон, крупный тёмный текст. Бирюзовый
используется для выбранного раздела, основного действия, блока урока и предметных
акцентов. Белые карточки, мягкие тональные блоки помощи, лёгкие границы и тени
повторяют макеты. Предыдущий запрет карточек/цветных состояний из quiet-темы здесь
заменён последним выбором владельца. Не подключать `quiet.css` обратно.

## Токены

Источник значений — `packages/ui/src/tokens.css`. Не размножать hex/font literals
в компонентах, не расширять legacy allowlist ради новых страниц.

Статусы не различаются одним цветом: сохранять подпись, при необходимости иконку.

## Шрифт и размеры

Локальный **Golos Text Variable**. Без внешнего font CDN и декоративного serif.
В кабинете ученика основной текст/контролы 18px, вспомогательные подписи 14–18px;
заголовки страниц 40px, разделов 26px, карточек 22–30px, feature 36–40px.
Mobile: заголовок страницы 30px, раздела 22px, основной текст 18px, навигация 14px.
Короткие подписи shortcuts 14–15px. Обычный tracking, веса 400–700; длинные строки
переносятся без обрезания существенного содержания.

## Компоновка

- Desktop sidebar 240px; шапка около 76px; горизонтальный отступ контента 32px,
  верхний 24px. Боковая навигация остаётся общей для роли; помощь ученику внизу.
- Внутренние страницы: breadcrumbs «Главная → раздел», затем h1 и одна короткая
  строка пояснения. Breadcrumbs описывают пользовательские разделы, не код/ID.
- Сетка основной области и правой колонки: `2.2fr / 1fr`, gap 24px. Правая колонка
  не уже 300px. Ниже 1440px она переносится под основной блок; до 768px — один столбец.
- Карточка: padding 24px, radius 20px, декоративная граница 1px, лёгкая тень.
  Плитки radius 16px, поля/кнопки 12px, основные touch targets не меньше 44px.
- Главная сохраняет свой hero + три shortcuts + предметы + рабочие списки.
  Не заставлять все страницы повторять её композицию целиком.

`student-calendar.tsx`: месячная дата-сетка; точки только по полученным урокам.

`skill-focus.tsx`: опубликованная обратная связь и предметная карточка.

Стили: `reference.css` — общая оболочка и home/CRM; `identity.css` — внутренняя
композиция, учебные карточки и responsive. Обе таблицы используют общие tokens.
Другие ученические страницы получают ту же шапку, h1, поля и поверхности.
Staff/CRM продолжают общую палитру и оболочку, сохраняя свою рабочую плотность.

Hero-фоны — реальные raster assets: `lesson-hero-reference.webp`,
`schedule-hero-reference.webp`, `knowledge-hero-reference.webp`. Не растягивать
ноутбук из узкой карточки на широкий баннер; для расписания есть отдельный фон.
Текст и действия остаются HTML. Иконки — существующая Lucide-семья, без рисования
иллюстраций в CSS/SVG; отсутствующее фото не подменять вымышленным человеком.

## Данные и смысл

- Макет не разрешает создавать занятия, оплаченные права, отзывы или контакты.
  Сроки и кнопки Meet по-прежнему определяются сервером; календарный день не меняет допуск.
- В расписании сохраняются периоды, server pagination, return URL, лимит календаря,
  перенос и спор. При ошибке месяца его навигация остаётся доступной.
- Счётчики ДЗ получаются из `total` существующего API отдельно для четырёх статусов.
  Не считать итогом школы количество карточек текущей страницы. Недоступный итог — «—».
- API списка ДЗ не принимает subjectId: предметный фильтр честно ограничен текущей
  страницей и так подписан. «На доработку» остаётся отдельным фильтром, поскольку
  сервер не поддерживает объединённую пагинацию NOT_SUBMITTED + NEEDS_REVISION.
- Файлы/комментарии показываются только при наличии DTO. История не означает,
  что файл доступен для скачивания: не конструировать download URL из fileId.
- Навыки имеют четыре технических состояния и три учебных этапа. NOT_STUDIED —
  отдельное состояние без оценки, не нулевой процент и не четвёртая ступень.
- «Навык в работе» — первый предоставленный навык FAMILIARIZING/PRACTICING,
  без утверждения о текущем уроке или связи с конкретным ДЗ. CTA ведёт в предмет;
  skill→homework связи в контракте нет. Feedback берётся из public audit этого навыка.
- Цели, срез после 4 уроков, отчёт после 8 и история остаются отдельными блоками.
  Допускается сворачивать их в details, сохраняя содержимое и пагинацию.
- Freshness можно показывать компактно; полные источник/получение/таймзона остаются
  в title/доступном имени. Read policy, mutation safety и editor state не менять ради картинки.

## Движение и доступность

`docs/UI_MOTION_2026_11_08.md`: 200ms enter ease-out, 160ms exit, dropdown 150–250ms,
stagger 30ms, press 0.97, происхождение от trigger, без spring bounce. Не анимировать
доступность действия. Сохранять reduced-motion, native labels, focus и keyboard.
Номера шагов у помощи/этапов и цветные статусы здесь являются частью выбранных
макетов; не удалять их только по старому списку AI slop.

## Как повторять и проверять

1. Прочитать этот файл, относящиеся требования и конкретный reference screenshot.
2. Использовать существующие компоненты/токены; добавить новый паттерн только при необходимости.
3. Собрать `pnpm preview:visual` и открыть IAB. Это локальная синтетическая школа,
   не production proof и не новый backend.
4. Сравнить source + render в одном изображении при 1672×941 для трёх новых макетов
   (home — 1536×1024), отдельно проверить фокусные области и 360/768/1280px, RU/RO.
5. Проверить loading/empty/error/disabled, основные переходы, поля, историю и editor.
   Не отправлять тестовые команды в production.
6. Targeted TypeScript/ESLint, `node scripts/k8k-design-check.mjs`, route budgets.
   Итог сохранять в `design-qa.md`, не объявляя его общей бизнес-приёмкой.
