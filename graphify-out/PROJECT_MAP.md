# Карта проекта «Онлайн-академия»

Исходный обзор **25 октября 2026, после решений CON-01—11**: 20 Markdown-документов, 7 макетов, 41 исходный JPG, одна видеозапись 13:51 и 17 отобранных кадров. Последующие инкременты и их отдельные ограничения приведены ниже; исходные количества — исторический снимок.

**Блоки №13 и №14 закрыты на уровнях архитектуры и технического проектирования. Утверждена стратегия реализации MVP-IMPL-01/B:** сначала полный общий фундамент данных и защищённых сервисов, затем последовательно **ученик → преподаватель → менеджер/CRM → публичный сайт**, отдельная QA-приёмка и регрессия каждого этапа. Полные предметные схемы, реализация и приёмка ещё не подтверждены. Следующий открытый вопрос — **MVP-IMPL-02**, критерий допуска фундамента FND-GATE.

**Фактический инкремент TASK-01:** создан pnpm/TypeScript ESM-monorepo с API, standalone worker,
React/Vite QA-оболочкой и пакетами db/api-contracts/shared. Установка, typecheck, build и lint
прошли; шесть локальных проверок подтверждают Result, фабрики Prisma без подключения к БД,
HTTP health и lifecycle worker. [Запуск и границы проверки](../README.md#разработка-task-01).
Миграции, предметные модели, outbox и полный FND-GATE этим инкрементом не закрыты.

**Инкремент TASK-02, проверка 26 октября 2026:** созданы 20 моделей Identity/Access/CRM
и общий AuthAccount, UUID, именованные FK, PII-разметка и две SQL-миграции.
На чистой PostgreSQL 18.6 прошли `prisma migrate dev`, validate/generate,
12 интеграционных проверок и регрессия TASK-01; `migrate diff` не выявил различий.
Частичные UNIQUE защищают активные Household/StudentAccount, EXCLUDE — историю
семейных периодов. [Подробности и воспроизведение проверки](../packages/db/README.md).
На момент TASK-02 финансовые UUID-ссылки активации не имели FK; это устранено
инкрементом TASK-03 ниже. RBAC/MFA-протоколы, outbox,
полная модель MVP и FND-GATE этим инкрементом не закрыты.

**Инкремент TASK-03, проверка 26 октября 2026:** добавлены 25 моделей Schedule/Finance/
Entitlements/Ledger/Payroll (всего 46), две миграции и 21 денежное поле Decimal(20,4).
Проверены ключи идемпотентности, отсутствие повторных списаний и отрицательного остатка
при конкуренции, закрытые периоды, раздельные подтверждения денег/выплат и финансовые FK
активации. Снимок ставки/исполнителя хранится при фактическом старте, без месячной отсрочки;
обычная шкала 200/220/250, индивидуальные обещания отделены.
NestJS-команда публикации проверяет все строки по каждой валюте, SQL/RLS защищают published.
Штатная policy запрещает публикацию до ACL TASK-06/08; финансового HTTP endpoint нет.
На чистой PostgreSQL 18.6 применены все четыре миграции, прошли 22 интеграционные проверки,
typecheck/build/lint и регрессия каркаса; migrate diff — без различий.
[Реализация, воспроизведение и границы проверки](../packages/db/FINANCE.md).
Полные доменные API, audit/outbox, банковская/правовая приёмка и FND-GATE остаются открытыми.

**Инкремент TASK-04, проверка 26 октября 2026:** добавлены 16 моделей Education/Files/
Audit/Outbox/Jobs и отдельная HomeworkDelivery по TECH-11/B; полная схема — 63 модели.
На чистой PostgreSQL 18.6 применена единственная `init`, seed добавляет только пять ролей:
первый запуск 5 вставок, повторный 0; повторные и параллельные вызовы сохраняют ID/timestamps.
Исходные четыре миграции сохранены с SHA-256 в migrations-history; для прежней БД есть
отдельный legacy upgrade 4→5, проверено сохранение контрольной Student-записи.
Прошли 31 интеграционная проверка и регрессия каркаса, typecheck/build/lint; schema diff — 0.
Публикация ledger теперь атомарно сохраняет audit и pending-outbox; коллизия откатывает
все три эффекта. Audit/file logs append-only, runtime не имеет UPDATE/DELETE для них.
Поддержаны версии ДЗ/оценок/отчётов, checkpoint 4/8, типизированные приватные file grants,
48-часовой TTL кэша идемпотентности и отдельная сверка UNKNOWN для каждой попытки job.
[Текущая модель, обе migration chain и воспроизведение проверки](../packages/db/EDUCATION_INFRA.md).
Хранилища audit/outbox готовы; полное покрытие будущих команд аудитом, ACL, S3/Meet POC,
работающий dispatcher/worker, production GO и FND-GATE остаются открытыми.

**Инкремент TASK-05, проверка 26 октября 2026:** incremental guards поверх неизменной init:
teacher calendar EXCLUDE, unique платёж/абонемент и проверка баланса по валютам при публикации.
Полный синтетический QA seed с UUIDv5, 1 директором/2 менеджерами/2 преподавателями/3 Student,
расписанием и подтверждёнными финансами повторяется конкурентно без изменения ID/timestamps.
Шесть QA-тестов прошли. Чистая PostgreSQL 18 и локальный staging с предыдущей схемой
проверены; SHA-256 всех прикладных данных до/после upgrade совпал. Внешний staging не указан.
`db:reset-qa` отделён от seed; фактический reset остановлен встроенной защитой Prisma для AI,
данные не удалены. [Команды и доказательства](../packages/db/MIGRATIONS_SEED.md).

**Инкремент TASK-06, проверка 26 октября 2026:** подключено NestJS core с PostgreSQL
opaque sessions, CSRF, default-deny roles/permissions/student-context policies, MFA/challenge
lifecycle, request ID и едиными ошибками. Критические commands сохраняют business/Audit/
Outbox/idempotency response в одной SERIALIZABLE-транзакции; максимум три попытки.
Прошли четыре unit- и девять HTTP/PG тестов (401/403/422, конкурентный cache replay,
откат при audit/outbox отказе, revocation/TTL и актуальные назначения), прежние 31 DB-тест.
[Устройство и границы ядра](../apps/api/CORE.md). Identity добавлен следующим TASK-07 ниже;
финансовые API TASK-08, production GO и FND-GATE остаются открытыми.

**Инкремент TASK-07, проверка 26 октября 2026:** реализованы 12 Identity/registry операций,
SimpleWebAuthn 14.0.3 с реальной проверкой RP/origin/UV/signature/counter, session rotation,
browser-bound passwordless challenge и управляемое recovery без backup-кодов.
RecoveryAuthorization создаётся только trusted maintenance после внешней проверки;
для директора обязателен tech operator и подтверждённое поручение владельца. Runtime не
создаёт evidence; recovery сессия допускает только повторную регистрацию passkey.
Registry CRM создаёт Student без кабинета/прав, Household требует предметного контекста.
Добавлена третья migration и три модели (всего 66); прежние миграции не изменены.
Прошли 9 core + 11 Identity HTTP/PG сценариев, 31 DB- и 6 QA-тестов; проверены оба CLI.
Чистая PostgreSQL 18.6 и локальный upgrade заполненной TASK-06 схемы прошли status/diff,
значения старых колонок, ID и timestamps сохранены. [Контракты и runbook](../apps/api/IDENTITY.md).
Постоянный QA DNS/TLS и физические устройства ещё не проверены; внешний staging,
production GO/FND-GATE и предметные финансовые/расписательные команды остаются открытыми.

**Инкремент TASK-08, проверка 26 октября 2026:** реализованы все 17 Finance-операций:
подтверждение денег/распределения директором, полные оплаченные права, отдельный
ограниченный допуск при каждой неполной оплате, точный ledger по валютам, reversal и
каноническая замена закрытой истории, периоды, начисления и подтверждённые выплаты.
Менеджер ограничен назначенным учеником даже при replay cache; teacher читает свою
ведомость. SERIALIZABLE business/audit/outbox/cache атомарны; SQL запрещает двойное
списание и отрицательный остаток. Worker самостоятельно создаёт CRM-задачу по expiry.
Ставка фиксируется на фактический старт, обычная шкала 200/220/250; через 7 месяцев
стаж не восстанавливается, индивидуальные обещания сохранены отдельно. Четвёртая
incremental migration, 69 моделей, 23 денежных Decimal(20,4), прежний SQL не переписан.
Прошли 14 unit/smoke + 34 HTTP/PG + 31 DB + 6 QA = 85 автоматизированных тестов.
Чистая PostgreSQL 18.6 и upgrade заполненной TASK-07 схемы: status/diff без различий,
все прежние значения/ID/timestamps сохранены. [Finance/runbook](../apps/api/FINANCE.md).
Внешний staging, реальные переводы, юридические регламенты, production GO и FND-GATE
остаются открытыми. Следующий предметный инкремент — Schedule TASK-09.

**Инкремент TASK-09, 26 октября 2026:** подключены 13 заданных Schedule-операций и
две команды генерации/серверного старта. Стабильный ключ slot/local-date, перенос
того же lesson_id, история шаблонов и календаря; DST с явным разрешением неоднозначности.
Преподаватель работает со своей свободной доступностью и запросами менеджеру;
сообщение о проведении отделено от подтверждения. 24h/⭐ worker создаёт только
внутренние задачи, без автоматического проведения, списания, начисления или долга.
Пятая migration: 72 модели. До изменения стратегии проверок прошли 13 HTTP/PG и
две DST-проверки, upgrade заполненной TASK-08 схемы сохранил 30 прежних записей,
ID/timestamps; schema diff 0. [Schedule](../apps/api/SCHEDULE.md).

**Инкремент TASK-10, 26 октября 2026:** Swagger UI/JSON, OpenAPI 3.1.0/v1, metadata
46 реальных API-операций, классы DTO с class-validator и строковыми денежными полями.
Orval SDK хранится в исходниках, импортируется QA-shell; генерация и короткий smoke
UI/JSON/$ref/SDK прошли. [Контракты](../apps/api/OPENAPI.md).
Git-коммит не создавался: рабочая папка не является Git-репозиторием.

**Инкремент TASK-11, 26 октября 2026:** отдельный worker получил PostgreSQL outbox
с SKIP LOCKED, устойчивыми JobRecord/JobAttempt, lease/reclaim, идемпотентными handlers,
backoff 1s/5s/30s/5min/30min и DEAD с аудитом. Шестая миграция добавляет статус outbox
и переводит RecoveryState в PENDING/CONFIRMED/FAILED/NEEDS_MANUAL с сохранением
доказательств; слепой повтор внешних операций остаётся запрещён SQL guard.
Адресная компиляция/ESLint, 2 unit/lifecycle и 12 PostgreSQL 18.6 smoke прошли,
включая SIGKILL/restart, конкуренцию и отсутствие дублей. S3/Meet сверка подключается
через RecoveryProvider; реальные адаптеры/POC и итоговый gate остаются открытыми.
[Контракт, запуск и ограничения](../apps/worker/WORKER.md). Ранние упоминания
неработающего dispatcher в TASK-04 описывают состояние того инкремента.

**Инкремент TASK-12, 27 октября 2026:** React/Vite оболочка опубликована на постоянном
`https://onlineschool-xi.vercel.app` в единственном рабочем Vercel/Neon-проекте владельца.
Реальные password/WebAuthn enrollment/authentication проверены в Chromium на этом origin;
менеджер/директор/преподаватель используют обычные роли, MFA и сгенерированный SDK.
CSRF, UUID idempotency, status/migration info, файловые разрешения и responsive UI проверены
адресно. Временный опубликованный test-account отключён; ключ владельца регистрирует владелец.
[Реализация и границы](../apps/qa-shell/QA_SHELL.md). Опубликованный worker относится к TASK-14.

**Инкремент TASK-13, 27 октября 2026:** Compose API/worker/PostgreSQL18/nginx и одноразовые
миграции запускаются с раздельными app_migrate/app_runtime; runtime не владелец и не меняет
audit, ledger RLS сохранён. Локальные startup/permission/TLS/persistence smoke прошли;
после пересоздания PostgreSQL-контейнера контрольный hash ролей сохранился. В GitHub
[PR #1](https://github.com/EsinencuP/OnlineSchool/pull/1) все шесть jobs зелёные на
`4016ca9cc2b6c31f2d6bff90fd653863c920414e`, 90 существующих интеграционных тестов прошли
на реальном PostgreSQL18. Устаревшая outbox fixture приведена к DELIVERED без ослабления SQL.
Публичный GitHub содержит source-only историю; локальная история с видео 276 МБ сохранена,
секреты/корпус/media не экспортированы. На окончание TASK-13 PR ещё не merged;
публикация и merge выполнены следующим инкрементом TASK-14.
[Runbook](../infra/README.md), [доказательства](../infra/TASK13_EVIDENCE.json).
Это доказательства инфраструктурного TASK, не полный TASK-15/FND-GATE и не production GO.

**Инкремент TASK-14, 27 октября 2026:** используется единственный рабочий проект
`onlineschool` по `https://onlineschool-xi.vercel.app` и существующая Neon main
`online_school` (PostgreSQL 18.6, Frankfurt). Дополнительных QA/staging/shadow/test
проектов, веток или БД не создаётся. По прямому уточнению владельца job integration-test
теперь явно skipped; синтетические/destructive suites не запускаются на рабочей БД.
Это ограничение текущего CI, а не прохождение DB-регрессии.

Worker опубликован как настоящий Vercel Daemon, одна instance fra1, с PostgreSQL
outbox/reconciliation и SIGTERM drain. API/worker health и Swagger возвращают 200,
свежий heartbeat подтверждён в Neon; SHA отображается в браузере. PR #1 объединён
в main, Vercel Git integration автоматически собирает новый commit и выполняет
direct `prisma migrate deploy` до публикации; DB credentials не передаются GitHub.
Точный SHA публикации/проверок и ограничения — в
[протоколе TASK-14](../infra/TASK14_EVIDENCE.json),
[runbook](../infra/vercel/README.md). Это публикация MVP, не production GO или FND-GATE.

**TASK-15, 27 октября 2026 — частичная проверка, FND-GATE заблокирован:**
структура tests/unit/integration/api/concurrent/e2e, Jest/Supertest/Playwright,
реальные роли и MFA. 29 разрешённых Jest-проверок прошли; 2 Chromium WebAuthn E2E
прошли на рабочем HTTPS origin. Временные обычные MANAGER-аккаунты отключены,
роль завершена, ключи/сессии отозваны, изменения и cleanup записаны в audit.
Рабочая финансовая история не использовалась и не менялась.

Read-only Neon PostgreSQL 18.6: ERD/Prisma совпали с 73 таблицами, 818 столбцами,
164 FK и семью checksum миграций; проверены exclusions/unique/audit/RLS/grants.
Каталог сохранён с timestamp: его повторная проверка в CI не равна живой DB-регрессии.
Владелец прямо подтвердил «без одноразового PostgreSQL». Дополнительных БД/веток/
контейнеров не создавалось; чистая/предыдущая схема, полные финансовые гонки и
crash/reclaim на допустимой цели не проверены. Foundation gate возвращает failure
после разрешённых проверок, чтобы не превратить пропуски в зелёную приёмку.
[Draft PR #2](https://github.com/EsinencuP/OnlineSchool/pull/2),
[матрица статусов](../tests/FOUNDATION_STATUS.json),
[протокол](../infra/TASK15_EVIDENCE.json). TASK-15 не закрыт; FND-GATE и production GO
не выданы. Исторические 90 тестов TASK-13 остаются только прежними доказательствами.

**Новый порядок проверки фазы 0 (прямое указание владельца 26.10.2026):**
не повторять масштабные проверки на каждом TASK; только необходимые адресные
компиляция/генерация/короткий smoke. Общая регрессия после TASK-10 и полная приёмка
отложены на конец фазы 0. [Чек-лист](../PHASE0_CHECKS.md). Исторические доказательства
TASK-01—09 не означают прохождение нового общего gate. FND-GATE/production GO открыты.

## Утверждённая техническая основа

**Backend:** модульный монолит TypeScript/NestJS, PostgreSQL, Prisma/Migrate, REST/OpenAPI и TS-клиент. **Frontend:** React/TypeScript/Vite SPA; отдельный публичный SSG с Git/Markdown-контентом. **Доступ:** серверные cookie-сессии, контекстный RBAC, MFA персонала, аудит. **Надёжность:** транзакции, PostgreSQL outbox/worker, внешнее приватное S3. **Инфраструктура:** Compose на одном VPS, внешний backup, staging и проверяемое восстановление.

Это принятые выборы; конкретные версии, схемы и конфигурации ещё нужно создать. TECH-09/C задаёт единый денежный ledger, TECH-08/B — отдельные количественные права на уроки. TECH-04/C и TECH-05/A вводят историзируемую семью и не более одной активной семейной группы на ученика; семейная связь не заменяет проверку полномочий. STOR-01/B разрешает Google Drive только для рабочих файлов сотрудников, не как хранилище или backup платформы.
