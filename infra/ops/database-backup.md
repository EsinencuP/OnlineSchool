# Резервное копирование PostgreSQL

## Действующая конфигурация

На 20 ноября 2026 рабочий проект `onlineschool` использует PostgreSQL 18
и Neon Free с окном истории 6 часов. Для `main` создан ручной снимок
`onlineschool-recovery-baseline-2026-11-20` (`snap-frosty-union-b9dnz87e`).
Запрос ежедневного расписания отклонён, а повторное чтение расписания
вернуло пустой список. Снимки по расписанию доступны на платных планах.
[Документация Neon](https://neon.com/docs/guides/backup-restore)

Задача Windows `OnlineSchool PostgreSQL Daily Backup` запускает `pg_dump`
ежедневно в 03:15 по местному времени на текущей машине, когда пользователь
вошёл в Windows. Пропущенный запуск выполняется при следующей возможности
в той же сессии. Проверить результат можно через
`Get-ScheduledTaskInfo -TaskName 'OnlineSchool PostgreSQL Daily Backup'`.
Код `0` подтверждает успешное создание архива.

Копии находятся в `%LOCALAPPDATA%\OnlineSchoolBackup\archives`.
Данные шифруются AES-256-GCM на лету. Windows DPAPI по текущему пользователю
защищает ключ архива и строку подключения в `config.json`. Подключение
идёт напрямую к Neon с проверкой сертификата и имени хоста под отдельной
ролью `onlineschool_backup`, которой выданы права чтения, включая строки
под RLS. Файл становится доступен под окончательным именем после успешного
завершения выгрузки. Скопированная задача запускается из защищённого каталога.

- Снимок Neon поднят как отдельная ветка
  `recovery-drill-2026-11-20` с собственным вычислительным узлом. Ветка
  готова и настроена на истечение 21 ноября в 23:30 по Кишинёву.
- Зашифрованный архив `online_school-2026-11-20T21-28-35.291Z-d6bbc8.pgdump.enc`,
  созданный запуском задачи Windows, аутентифицирован и восстановлен в пустую
  локальную PostgreSQL 18. Владельцы и разрешения из архива сохранены.
- Аудит восстановленной базы дал `CHECKPOINT_MATCH`. Совпали 56 миграций,
  контрольные отпечатки 22 наборов данных и 11 проверок инвариантов.
  Роль `app_runtime` прочитала штатную версию миграции и не имела права
  удалять записи аудита. Отпечатки 22 наборов из ветки снимка также совпали с
  контрольной выборкой `main`.

  Локальный кластер репетиции остановлен. Его данные остаются в каталоге

## Повторение восстановления

Подготовьте пустую PostgreSQL 18 на `127.0.0.1` с именем базы
`online_school_restore_<id>`. До восстановления создайте в отдельном
кластере роли, упомянутые в архиве, включая `school_owner`,
`online_school_runtime` и роли инфраструктуры Neon `neon_superuser`,
`cloud_admin`. Для проверки прав роли-подстановки создаются с `NOLOGIN`.
Подключение к цели задаётся через защищённое окружение
`ONLINESCHOOL_RESTORE_URL`. На этой машине архив восстанавливается командой:

```powershell
$root = Join-Path $env:LOCALAPPDATA OnlineSchoolBackup
& "$root/database-backup-windows.ps1" -Config "$root/config.json" -RestoreArchive $archive
```

Проверьте восстановление через `database-recovery-audit.mjs --checkpoint`
и только после проверки допускайте запуск приложения или worker на копии.

Локальная копия независима от Neon, но доступна только при сохранности
машины, профиля и ключа. Пока разрешено только локальное хранение,
внешнее S3-хранилище и выносной ключ не настроены. Дамп восстанавливается
на момент выгрузки. Для внешнего PITR нужен физический базовый бэкап и
совместимый непрерывный архив WAL. `pg_dump` не поддерживает воспроизведение
WAL. Требование ARCH-14 по внешнему PITR и совместной проверке S3 остаётся
открытым. [Документация PostgreSQL](https://www.postgresql.org/docs/18/continuous-archiving.html)
