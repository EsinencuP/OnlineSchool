# Границы безопасности QA

- Координатор пропускает канонический HTTP(S) loopback origin и совпадающий live marker. Для изолированного удалённого стенда нужен согласованный локальный туннель с тем же marker и безопасной ссылочной политикой приложения. Рабочие и production URL исключены.
- Оператор подтверждает datasource, synthetic fixtures, внешние mock/disabled адаптеры и режим записи. Marker — декларация среды. QA не может автоматически установить, куда направлены backend, БД и фоновые работники. При сомнении в источнике данных или доставке действий останови проверку.
- Ролевые процессы получают `shell_tool=false`, sandbox read-only, отдельный cwd, отключённые дополнительные MCP, hooks, приложения и плагины. Координатор не передаёт чужие отчёты или исходники. Операторский запуск нативного агента в общем чате наследует MCP и разрешения чата. Используй команды проекта для работы с проверенными ограничениями.
- Playwright запускается с `--isolated`, отдельным процессом, настройками origin и списком разрешённых UI-инструментов. Посредник фильтрует прямую навигацию и имена файлов. Скрипты в браузере, сырые сетевые запросы, загрузка произвольных файлов и API отсутствуют в ролевом наборе. Allowlist Playwright и ограничение навигации усиливают правила прогона. Для жёсткой сетевой изоляции требуется отдельный firewall или изолированная среда.
- Учётные данные передаются Playwright через отдельный временный dotenv. Codex получает имена `QA_LOGIN` и `QA_PASSWORD`. Темп-конфигурация удаляется после попытки. Отчёты и скриншоты сохраняются локально вне Git. Используй только синтетические данные. Секреты, cookies, MFA-материалы и реальные семейные данные исключены из отчётов.
- QA Engineer использует read-only sandbox и отдельный worktree. В числах receipt отмечаются вызовы shell и файловые изменения. На проверку команд остаются ограничения контракта и изоляции стенда. Не подавай переменные продуктивной среды и не используй старые инструменты публикации.
- Ролевой тест может увидеть только доступное в UI. Для серверных проверок доступа QA использует ревью и существующие защитные тесты с синтетическими данными.
- Запрещены реальные платежи, возвраты, сообщения, встречи, удаление данных и смена права на рабочем окружении. В режиме `writes: blocked` фиксируй сценарии записи как BLOCKED. Для `synthetic-only` доступны только утверждённые синтетические действия стенда. Playwright фильтрует инструменты, семантика кнопок контролируется стендом и ролевым сценарием.
