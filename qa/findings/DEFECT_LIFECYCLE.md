# Жизненный цикл дефекта

`OPEN → TRIAGED → ACCEPTED → IN_PROGRESS → FIXED → READY_FOR_RETEST → VERIFIED`

`READY_FOR_RETEST → REOPENED` при повторном проявлении. Из REOPENED можно вернуть на triage или начать исправление. REJECTED характеризует обоснованное ложное срабатывание. DEFERRED требует ссылки на решение владельца и является записью принятого риска. История хранится отдельными append-only событиями. VERIFIED устанавливает только независимый повторный тест. BLOCKED оставляет дефект готовым к повторному испытанию.

| Приоритет | Условия |
|---|---|
| P0 | Угроза данным, авторизации, финансам или критической истории. Релиз и небезопасная часть прогона блокируются |
| P1 | Основной путь, расписание или обязательная операция недоступны. Блокирует этап до исправления или формального решения |
| P2 | Второстепенный функциональный или UX-дефект |
| P3 | Незначительное несоответствие, например визуальное |

Поддерживаются BUG, SECURITY, PERFORMANCE, UX, REGRESSION, DATA_INTEGRITY, ACCESSIBILITY, ENHANCEMENT, PRODUCT_DECISION. Последние два остаются в исходных отчётах и решениях сведения. Подтверждённые карточки получают ID `K8K-QA-<CYCLE>-<NUMBER>`. Указывайте `UNKNOWN` для неизвестного поля. Первопричина может связать несколько наблюдений. Исходные отчёты и ссылки на каждое наблюдение сохраняются.
