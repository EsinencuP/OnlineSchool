# Матрица защитных проверок

Используй ревью кода, конфигурации и существующих автоматических утверждений с синтетическими фикстурами. Указывай четыре измерения проверки. Проверка интерфейса дополняет проверку решения серверной политики.

| ID | Роль | Действие и ресурс | Контекст и ожидаемая защита |
|---|---|---|---|
| SEC-01 | Аноним / любая | Вход, сессия, восстановление, MFA | Ошибки и лимиты не раскрывают учётные записи, сессии и user state. Сверить действующий контракт |
| SEC-02 | Student | Расписание, задания, отчёты, файлы | Собственные данные разрешены, чужая принадлежность и неопубликованное закрыты по server guard |
| SEC-03 | Teacher | Ученики, материалы, начисления | Учитываются назначение, срок, распространение материалов и собственность выплаты |
| SEC-04 | Manager | Заявка, слот, заявленный платёж | Разрешённый scope и назначение, финансовое подтверждение ограничено ролью |
| SEC-05 | Director | Денежное решение, возврат, закрытый период | Авторизованная роль, обязательный контекст/MFA, целостность истории |
| SEC-06 | Все | Изменение формы, DTO, вывод, SQL и загрузка файлов | Анализ CSRF, CORS, заголовков, экранирования, параметризации и storage ACL |
| SEC-07 | Система | Логи, секреты, поставщики | Минимизация данных, ротация и маршруты доверия, отсутствие чувствительного содержимого в отчётах |
| SEC-08 | Все | Отзыв сессии, устаревшие права и role switch | Повторное решение на сервере по действующим правам, даже когда старый интерфейс ещё открыт |

Не формируй эксплуатационные шаги или payload. Для отказа авторизации используй результаты существующих защитных тестов и анализ политики. Невыполненный сценарий записывается BLOCKED или NOT_RUN.
