# Общая матрица

| ID | Этап | Проверка |
|---|---|---|
| FND-01 | FND-GATE | Трассировка задания, Git, сборка, схема и тестовая база |
| FND-02 | FND-GATE | Здоровье API, повторяемость контрактов, интеграция worker/outbox |
| FND-03 | FND-GATE | Миграции на разрешённой базе, ограничения и финансовый ledger |
| FND-04 | FND-GATE | Безопасность, производительность и доступность по профильным матрицам |
| ST-GATE | STUDENT-GATE | Student matrix, затем регрессия принятого фундамента |
| TE-GATE | TEACHER-GATE | Teacher matrix и регрессия ранее принятых компонентов |
| CRM-GATE | CRM-GATE | Manager и Director, затем регрессия фундамента, ученика и преподавателя |
| PUB-01 | PUBLIC-GATE | Публичные маршруты, RU/RO, форма заявки, согласие, заявка в CRM на синтетическом стенде |
| XFLOW-01 | RELEASE-GATE | Сквозная отдельная проверка CRM → ученик → расписание → урок → учебный результат → права и финансы |
| REL-MEET | RELEASE-GATE | Провайдерский Meet API, OAuth, операции и reconciliation по REL-01/A |
| REL-OPS | RELEASE-GATE | Проверенные backup/restore, мониторинг, эксплуатационная готовность и критерии ARCH-31/B |

Для каждого ID фиксируются PASS, FAIL, BLOCKED или NOT_RUN, доказательство и commit. Применимость зависит от утверждённого этапа и изменений. Существующий FND-порядок и состояние см. в PHASE0_CHECKS.md и tests/FOUNDATION_STATUS.json. XFLOW-01 требует отдельного прогона поверх четырёх ролевых отчётов. Требования Meet указаны в REL-MEET и в релизном дополнении.
