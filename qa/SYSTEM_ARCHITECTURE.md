# Архитектура QA-системы

Пять определений профилей находятся в `.codex/agents/`. Девять явных Skills направляют вызовы в `qa/scripts/qa.mjs`. Координатор начинает отдельные ephemeral-процессы Codex CLI с developer instructions соответствующего TOML. Он сохраняет структурированный результат и обезличенный receipt инструментов. Вызовы используют действующую ChatGPT-сессию. Открытие нового чата в интерфейсе и API-ключи не нужны.

По умолчанию технический агент работает с detached sparse worktree указанного commit. Ролевой процесс запускается во временной папке вне репозитория с отдельным Playwright MCP. Роли получают только свою матрицу, manifest сборки и имена тестовых секретов. Исходные отчёты собирает только координатор. Установочный стенд отличается в журнале по `environment: self-test`.

Порядок `qa_engineer → student_agent → teacher_agent → manager_agent → director_agent → consolidation`. Техническое отсутствие основы для безопасного прогона или критический security/data-integrity риск останавливает следующий аудит. Marker проверяется до и после каждого сеанса. Изменение сборки останавливает прогон. Координатор хранит отдельные результаты, зарегистрированные карточки, пакет разработчику и новые записи журнала, в том числе ретест.

Пакет открывает дефекты в статусе OPEN. Владелец фиксирует triage, принятие или риск. Разработчик работает по принятым карточкам. Ретест привязывается к сборке с указанным fix commit, повторяет исходные шаги и регрессию. Пакет предыдущего цикла и отчёты сохраняются.

## Этапы допуска

| Очерёдность | Gate | Свидетельства |
|---|---|---|
| FND-00 | FND-GATE | Фундамент по PHASE0_CHECKS и актуальным решениям |
| UI-01 Student | STUDENT-GATE | Матрица ученика и регрессия принятого |
| UI-02 Teacher | TEACHER-GATE | Матрица преподавателя и регрессия принятого |
| UI-03 Manager/CRM | CRM-GATE | CRM, наблюдения директора и регрессия принятого |
| WEB-04 Public Site | PUBLIC-GATE | Публичные потоки и интеграция с CRM |
| INT-05 Release | RELEASE-GATE | Сквозной прогон, Meet API, эксплуатация и решение по ARCH-31/B |

Gate передаётся через `--gate` и сохраняется в отчётах. Итогом журнала служат доказательства для владельца. Отдельный цикл с четырьмя ролевыми отчётами дополняет сквозной релизный тест. Порядок и текущий статус MVP-IMPL-02 сохраняются.
