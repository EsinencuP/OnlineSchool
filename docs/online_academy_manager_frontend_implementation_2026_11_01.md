# MGR-10 — реализация frontend, 01.11.2026

Статус: код S1–S6 и адресные проверки готовы; реальная интеграционная приёмка
на чистой БД, общий gate и публикация не выполнены. Это отчёт реализации,
а не новое утверждение бизнес-правил или разрешение создавать тестовую БД.

Шаг0 сверил существующий `apps/student-cabinet`: общего UI workspace нет.
Менеджер размещён отдельно в `apps/manager-web`, с теми же закреплёнными версиями
React/Vite/Router/Query/Zustand и нативными React-формами. Все семь экранов и
шесть вкладок карточки используют только Orval. Vercel wiring подготовлен для
`/manager/...`, но deployment build с миграциями не запускался.

Сохранены решения владельца MGR-02…09: денежный остаток только по опубликованным
движениям абонементов; MDL; первая оплата через готовое распределение; 30/60 дней
заморозки по направлению; минимум60 минут; директорское исполнение исключений
и полной отмены списания; частичные запросы — отдельное Finance-решение;
202 уведомления означает очередь. Менеджерский UI не создаёт обходов директора.

Для выбора именованных предметов, тарифов, направлений, назначенных преподавателей
и финансовых периодов добавлен `/api/v1/manager/options`. Student-specific чтение
проходит общий portfolio scope, чужой/отсутствующий ученик неразличимы. Общий
справочник показывает только имена своего портфолио. Нет контактов/семейных сумм
в справочнике, новых таблиц, миграций и business Audit. Даты остаются ISO;
в интерфейсе используется timezone `/me`.

Пароль выдаётся на отдельном экране без Query/Mutation cache, browser storage,
URL или аналитики; уход/401/выход и отмена позднего ответа проверены. CSRF/cookies,
идемпотентность, безопасные ошибки с requestId, сохранение текста при409,
доступность и адаптивность включены в адресные проверки. ESLint блокирует float-
преобразования денег, ручной fetch и HTML sink; отдельный тест проверяет эти запреты.

Vitest/Testing Library:14 проверок. Playwright/MSW:13 проверок, включая СЦ-М-01…05,
axe и360/768/1280. Это синтетическая модель, типизированная OpenAPI DTO, не проверка
реальных транзакций Finance/Schedule/Identity. CI job использует только эту модель.
JS entry около84.5 KiB gzip, dashboard142.3 KiB; бюджет250 KiB проверяет build manifest.

Подробности — `apps/manager-web/README.md`, результаты/хэши —
`tests/evidence/mgr10-verification.json`. Полный recursive прогон отложен согласно
`PHASE0_CHECKS.md`; политика одной рабочей Neon main сохраняется. Реальный
authenticator, чистая/предыдущая схема, внешняя доставка и MGR-09 p95 не подтверждены.
Исторические отчёты предыдущих задач и закрытые источники не переписаны.
