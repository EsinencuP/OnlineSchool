## 1. Решение и приоритет правил

**Выбрано A:** расширенную интеграцию Google Meet REST API **включить в обязательный scope первого образовательного MVP**. До 2026-10-25 конфликт `ARCH-22/C` ↔ `DEV-01/B` был релизно не разрешён: `ARCH-22/C` утверждал целевую архитектуру, но сам по себе не расширял первый выпуск. Настоящее **отдельное явное одобрение** включает Meet-интеграцию в первый релиз **как исключение из стандартного ограничения DEV-01/B на дополнительные интеграции**. `DEV-01/B` в остальной части неизменен: образовательный процесс, исключение встроенных платежей, нативных приложений и расширенной аналитики сохраняются. `ARCH-22/C` не отменяется и не переписывается; технический способ — `TECH-15/B`.

**Не путать два статуса:** `REL-01/A` **закрыт как выбор релизного объёма**; `MEET-POC-01`, `MEET-OAUTH-01`, `MEET-SEC-01`, `MEET-QA-01` и `G4` **открыты до фактической реализации и приёмки**. Если POC выявит ограничение, запрещающее согласованный функционал, **нельзя молча перенести API во второй релиз, симулировать успех или считать базовую ссылку полной заменой**: открыть отдельный change request и получить новое явное решение владельца проекта по границе MVP. **Production GO отсутствует.**

## 2. Обязательный scope Google Meet для первого MVP

| ID | Компонент | Минимальная релизная обязанность / границы |
|---|---|---|
| `GM-SCOPE-01` | Пользовательское действие | Преподаватель — владелец утверждённого процесса создания/предоставления ссылки; создание Meet space из платформы только по аутентифицированному разрешённому действию владельца, без создания от имени произвольного педагога |
| `GM-SCOPE-02` | Google REST API | Реализовать типизированный серверный NestJS-адаптер для `spaces.create`, разрешённых `spaces.get` и только действительно нужных и разрешённых операций с настройками; сохранить источник, `spaces/{id}`, `meetingUri`, подтверждённые метаданные и время проверки |
| `GM-SCOPE-03` | OAuth | Пользовательский Google OAuth, минимальные scopes, защищённое хранение и обновление/отзыв токенов; проверить Google consent/verification/Workspace требования; **универсальный service account не предполагается** |
| `GM-SCOPE-04` | Постоянные ссылки | Одна постоянная ссылка на пару ученик–преподаватель; при смене преподавателя новая связь/ссылка, при переносе с тем же — прежняя; учёт истории ссылок/назначений, URL и ресурсного ID; meeting code не единственный долгосрочный ключ |
| `GM-SCOPE-05` | Отображение | Кнопка подключения к занятию по ранее утверждённому правилу за **10 минут**, с текущей серверной проверкой полномочий; ссылка не становится публичным ресурсом |
| `GM-SCOPE-06` | Проверка и диагностика | Раздельно отражать подтверждённые API-метаданные, отсутствие OAuth/недостаточность прав, недоступность API, неоднозначный результат и действительно подтверждённое отсутствие ресурса; нельзя обещать проверку любого URL, введённого вручную |
| `GM-SCOPE-07` | Сбои/повторы | PostgreSQL outbox/worker, дедупликация внутренних команд, ограниченные retry/backoff, reconciliation после таймаута; не создавать второй внешний space автоматически при неизвестном результате |
| `GM-SCOPE-08` | Ручной безопасный fallback | При недоступном API сохранять уже утверждённую рабочую ссылку с ясной диагностикой и рабочим процессом проверки/замены; fallback относится к **деградации**, не к исключению Meet API из приёмки MVP |
| `GM-SCOPE-09` | Инварианты предметной области | Google-метаданные/присутствие/открытие URL **не подтверждают проведённый урок, оплаченные права, списание или начисление**; authoritative source — PostgreSQL и утверждённые процедуры |
| `GM-SCOPE-10` | Граница данных | Не включать без отдельного утверждения автоматические записи, транскрипты, smart notes, отслеживание посещаемости детей, экспорт участников, Google Calendar-синхронизацию/массовые приглашения; S3/Drive стратегия `STOR-01/B` не меняется |

**Принципиально:** Google Meet REST API позволяет создавать пространства и читать/менять доступные сведения в пределах разрешений. Операции с чужими ссылками и некоторые настройки ограничены ролями, доступностью Workspace/Scopes; конкретные доступные возможности подтверждаются **POC до обещаний клиентам**. Google Calendar API допускается лишь при доказанной необходимости отдельного согласованного сценария `ARCH-22/C`; **не является обязательным новым источником расписания**.

## 3. Инженерные задачи и обязательные артефакты

| ID | Этап | Ожидаемый результат / доказательство |
|---|---|---|
| `MEET-POC-01` | Исследование на настоящих тестовых Google-аккаунтах | Матрица доступности `spaces.create/get`, ссылки через UI и Calendar (если релевантно), нужных OAuth scopes, ролей, типов аккаунтов, квот, ошибок 403/404/429, требований верификации и тарифа; зафиксированы **реальные** результаты и ограничения, не догадки |
| `MEET-OAUTH-01` | OAuth и владение | Схема связки педагог→разрешённый Google-аккаунт→согласие, шифрование секретов/refresh tokens, refresh/revoke, деактивация при уходе/смене назначения, отказ от избыточных scopes |
| `MEET-DATA-01` | PostgreSQL/Prisma/DDL | Ресурс Google space, внутренний ID пары, версии/история URL, creator/owner, времена последней проверки, API-диагностика, состояние попыток/outbox; constraint от конкурентных дублей |
| `MEET-API-01` | NestJS/OpenAPI | Прикладные команды и endpoint-контракты с RBAC, валидацией, идемпотентностью, auditing, typed adapter; клиент не получает токены и не обращается к Google API с секретом |
| `MEET-WORKER-01` | Очередь, восстановление | Устойчивое outbox/worker, timeout/unknown-result reconciliation, backoff/limits, dead-letter или операторское восстановление без бесконтрольных повторов |
| `MEET-UI-01` | React/CRM | Работа с парной ссылкой, статусом верификации, ошибками OAuth и сервисными задачами, подтверждённым правилом 10 минут; состояния недоступности корректны и доступны |
| `MEET-SEC-01` | Безопасность и правовая проверка | Scope review; защищённое хранение; доступ к чужим встречам невозможен; минимизация идентификаторов ребёнка, регистрация доступа, принципы retention/privacy; токены production не используются в Staging |
| `MEET-QA-01` | Приёмка Google | Автоматизированные тесты + тесты реального Google API для POC, отрицательные и конкурентные сценарии; доказательства приложены к Gate G4 и общему `E11` |

### Специальные случаи

- **Создание после таймаута:** результат Google может быть неизвестным и создание Meet space **не обязано быть идемпотентным со стороны провайдера**. Система сохраняет операцию с уникальным внутренним ключом; до нового создания выполняет сверку и при необходимости ручное разрешение, не создавая второй space вслепую.
- **Ручная ссылка стороннего владельца:** невозможность прочитать `spaces.get` означает **недостаточность доступа/непроверенный статус**, но не отсутствие реальной встречи.
- **Ротация преподавателя:** прекращение назначения отзывает **платформенный доступ** и соответствующие OAuth-связи согласно утверждённым правилам; старые уроки остаются историческими, новый преподаватель не наследует чужой Google ресурс.
- **Google outage:** сохраняется заранее известная разрешённая ссылка и CRM-маршрут устранения; без ложных подтверждений посещаемости.
- **Приватность детей:** записи, расшифровки, smart notes и автоматический сбор списка участников не включаются одним лишь `REL-01/A`.

## 4. Приёмочные сценарии нового релизного дополнения (план, не выполнено)

| ID | Вход/событие | Ожидаемый результат |
|---|---|---|
| `REL01-AT-01` | Разрешённый преподаватель проходит Google OAuth и создаёт space | Возвращённый `spaces/{id}` привязан к разрешённой паре; сохранены источник, URL, автор и аудит |
| `REL01-AT-02` | Недостаточные Google scopes или 403 на чужую ссылку | Не заявлять «встречи не существует»; корректная ошибка и CRM-восстановление |
| `REL01-AT-03` | Истёкший/отозванный refresh token | Авторизация/переподключение под контролем; платформа не раскрывает токены |
| `REL01-AT-04` | Два конкурентных запроса на создание для одной пары | Не более одной принятой актуальной привязки; повтор не создаёт лишний ресурс без reconciliation |
| `REL01-AT-05` | Таймаут/503 после отправки создания | Состояние `unknown`, сверка/операторское вмешательство; никакого слепого повторного создания |
| `REL01-AT-06` | Перенос урока с тем же преподавателем | Та же ссылка, а история расписания верна |
| `REL01-AT-07` | Смена преподавателя | Новая связь/ссылка, история прежних уроков сохраняется, токены и права бывшего учителя ограничены |
| `REL01-AT-08` | За 11 и за 10 минут до занятия | Кнопка доступна только в положенный момент и разрешённому пользователю |
| `REL01-AT-09` | Пользователь вошёл в Meet, но урок не подтверждён | Нет автоматической отметки проведения, списания, ledger-проводок и начислений |
| `REL01-AT-10` | Google outage/429 | Контролируемая деградация, retry/backoff, внутреннее уведомление, без дублей уроков и CRM-задач |
| `REL01-AT-11` | Тест в Staging | Нет prod OAuth токенов/PII, реальный изолированный POC; не выдаёт production полномочия |
| `REL01-AT-12` | Релизная приёмка | G4 не проходит без E8-GM и доказательств OAuth/POC/безопасности, даже если ручные ссылки работают |

Выполнение этих 12 проверок **не заявлено**. Сценарии `ARCH-22/C` (`MEET-AT-01—10`) и `TECH-15/B` (`TECH15-AT-01—16`) **сохраняются**; `REL01-AT-01—12` добавлены как релизная надстройка, без изменения ранее утверждённых наборов.

## 5. Изменение backlog MVP и релизных ворот

- `E8` — сохраняет типизированные Meet/S3 adapters и outbox, но расширенная Meet-интеграция **обязательна, P0**, а не «POC в разрешённом scope» без установленного решения. Развернуть `E8-GM-01—E8-GM-08`, описанные в актуальном `online_academy_MVP_implementation_backlog_v1.0.md`.
- `E0` — первым делом провести `MEET-POC-01` как внешний критический spike (параллельно фундаменту проекта) и задокументировать Google account/OAuth/Workspace ограничения; без успеха POC не обещать API-поведение.
- `E1/E6/E7/E9` — связать модель Meet resource, команды API, защиту токенов, UI и негативные тесты.
- `E11/G4` — расширенное API является условием достижения readiness. **G4 = pending**, пока нет успешных тестов и разрешений. Встроенный безопасный fallback не даёт автоматического `G4 PASS`.
- `STOR-01/B` — без изменений: приватный S3 платформы, Drive только внутренние рабочие документы; API Meet **не превращает Drive в StorageAdapter**.
