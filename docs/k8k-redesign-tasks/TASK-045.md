Спор/предварительное начисление/подтверждённая выплата различаются; личные обещанные обязательства не отменять молча.

## 5. Предметные правила и сохранение поведения

- Teacher identity из собственной сессии; teacherId в существующем path проверяется на владельца, деактивацию, MFA и актуальную session policy.
- Обычные ставки:0–4 points200,5–9 points220,10 points250; не линейные5MDL/очко, не +20/+30 и не обычные230.
- Изменение применяется к будущим подходящим урокам со snapshot при actual start; не ждать первого числа и не пересчитывать прошлое по текущим KPI.
- Индивидуально обещанные обязательства сохраняются по действующим promises; диапазон обычной ставки не разрешает молча обрезать специальную обещанную сумму.
- Начисление, признанное обязательство, попытка выплаты, UNKNOWN/FAILED и confirmed payout — разные факты. Закрытие месяца не означает, что деньги выплачены.
- Семейные поступления, цены абонементов, academy margin и коллеги не входят в teacher DTO, поиск, график или экспорт.
- Денежные значения остаются decimal strings/серверным Decimal; браузер не использует Number/parseFloat, calendar-count×rate и не складывает валюты.
- Стандартная поздняя отмена — отдельная200MDL компенсация без бонуса; реально проведённый неоплаченный урок/спор не отображаются как автоматический ноль.
- Нет teacher финансовых write-команд; любой спорный вопрос ведёт к собственному обращению, не к прямой корректировке ledger.

## 6. Контракты, данные и совместимость

- Существующий GET /api/v1/finance/teacher/:id/payroll/getTeacherPayroll переиспользуется/расширяется совместимо. Новые rate/period reads явно документируются как новые операции, не как готовый старый контракт.
- Own teacher lookup и ACL выполняются сервером; input period/pagination не меняют actor. Response содержит source/period/asOf/freshness и decimal-string amounts.
- Historical amount/rate/points/basis читаются из immutable accrual/outcome snapshots; current quote не перезаписывает их и не воспринимается как гарантия будущего безусловного дохода.
- Confirmed payout учитывается только из подтверждённой денежной публикации; PENDING/UNKNOWN attempt не попадает в «Выплачено». Corrected entries сохраняют связь с исходным периодом.
- Недоступная категория не заменяется0; валюты и статусы отдельны. Forbidden/revoked и транспортная ошибка не превращаются в пустую ведомость.

Точные имена новых planned DTO/operation/props запиши в коротком design note этого TASK до реализации и соблюдай существующие namespace/style. Planned нельзя выдавать за уже существующий API. Найденный существующий сервис переиспользуй. Generic UI не принимает бизнес-решения. Существующий авторитетный источник не копируется во второй реестр.
