# QA: вход по паролю и переходы в кабинеты

Последнее решение владельца от 01.11.2026: на существующем Vercel обеспечить
вход по логину и паролю для каждой роли, убрать passkey из QA, добавить переходы
в кабинеты ученика и менеджера и опубликовать действующие логины/пароли в README.
После пояснения, что README публичный, владелец явно подтвердил публикацию.
Доступы к инфраструктуре, БД, S3 и Vercel это решение не затрагивает.

Это расширяет прежнее решение `manager_password_login_owner_decision_2026_11_01.md`:
при `QA_PASSWORD_ONLY_LOGIN=true` парольная сессия доступна активным аккаунтам
с одной соответствующей ролью DIRECTOR, MANAGER, TEACHER, STUDENT или TECH_OPERATOR.
Флаг задаётся только на сервере production-проекта `onlineschool`.
Выбор учётной записи в форме подставляет login, но не назначает роль.

Сервер сообщает `password_only: true`. `mfa_completed` остаётся false,
`mfa_verified_at` не устанавливается. Режим не распространяется на recovery-only
сессии и некорректные сочетания account kind/ролей. При выключенном флаге сохраняется
прежняя политика, включая отдельное старое исключение менеджера, если его флаг включён.
При возвращении обязательного passkey необходимо также вернуть его интерфейс QA.

Проверки роли, назначений, портфолио, CSRF, отзыва и деактивации сессий сохраняются.
Студент не получает staff API; директор/преподаватель/техоператор не получают
manager API; менеджер не получает директорские финансовые решения. Создание новой
сессии не является имперсонацией и не переключает пользователя между ролями.

Использованы существующие аккаунты менеджера и ученика. По запросу владельца
добавлены отдельные QA-аккаунты директора, преподавателя и техоператора. Настройка
ограничена тремя фиксированными login/role, точным Vercel project ID и 30-минутным
окном; хеши паролей передаются только в защищённую build-конфигурацию. При коллизии
login аккаунт и пароль не переписываются. Auth/profile/role + Audit/Outbox атомарны.
Новых учеников, финансовых документов, уроков и оплаченных прав не создаётся.
После настройки её окно выключено, переданные build-хеши очищены.

На Vercel проверяются реальные login/current-session/logout для всех пяти ролей,
QA → student/manager без повторного входа, состояние API/DB/worker и отказы 403
для чужих кабинетов. Проверка не выполняет финансовые/учебные мутации и не заменяет
полную миграционную, конкурентную и финансовую приёмку FND-GATE.

Доказательства: `tests/evidence/qa-password-login.json` и
`tests/evidence/qa-password-production.json`. Доступы и ссылки — в начале README.
