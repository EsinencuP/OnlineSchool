# MGR-05 — валюта поступлений и действующие финансовые ограничения

Дата: 31.10.2026. Дополнение к пакету задач кабинета менеджера.

## Подтверждённое решение владельца

На вопрос о поддерживаемых валютах при регистрации поступлений MGR-05 владелец ответил: «mdl».
Новые поступления регистрируются только в **MDL**; пропущенная валюта означает MDL.
API использует код ISO в верхнем регистре. Старые поступления в других валютах сохраняются
и читаются без пересчёта и переписывания истории.

## Применение уже утверждённых правил

Это не новые разрешения менеджеру. Действующие `PaymentsService.confirm/approve`,
`PolicyService`, политика публикации Ledger и SQL-проверка директора требуют роль DIRECTOR
для подтверждения поступления и утверждения распределения. Поэтому manager-confirm переводит
PENDING → AWAITING_APPROVAL; директор публикует через существующий Finance endpoint.
Ни полной оплаты, ни принадлежности контакта портфолио недостаточно для обхода этого ограничения.
Противоречащий этому пункт исходного MGR-05 про публикацию менеджером не применяется.

Сохраняются ранее утверждённые уточнения:

- `PaymentReceipt.student_id` — контакт CRM; видимость поступления определяется портфолио контакта.
- Деньги ученика — опубликованные CUSTOMER_ADVANCE его абонементов по валютам; сумма поступления
  и нераспределённый остаток семьи в баланс ученика не включаются.
- MGR-03 проверяет опубликованное распределение. MGR-04 принимает готовое распределение;
  одна операция абонемента потребляет distributionId, а не весь paymentId.
- Каждое новое распределение при неполной суммарной оплате требует отдельного ограниченного
  решения директора. Предыдущие действующие допуски отзываются при утверждении нового распределения,
  включая решения с тем же timestamp. Согласованная рассрочка исключения не создаёт.
- При полной суммарной опубликованной оплате используются обычные оплаченные права без дублирования.
