# MGR-06 — подготовка занятия и директорские исключения

Дата: 31.10.2026. Дополнение к пакету задач кабинета менеджера.

## Явные решения владельца

1. На вопрос о значении `LESSON_MIN_LEAD_MINUTES` по умолчанию для создания и переноса
   урока владелец ответил: **«60»**. Значение по умолчанию — 60 минут.
2. На предложение сохранить отдельное решение руководителя для позднего переноса без
   потери оплаченного права и третьего переноса ученика владелец ответил:
   **«Сохранить решение директора»**.

`overrideLateRule` с причиной фиксирует запрос исключения. Сам флаг менеджера не разрешает
изменить занятие. Директор рассматривает конкретный урок, его текущую ревизию и точный
вариант изменения; одобрение применяется только один раз к этому варианту.

## Применение действующих регламентов

Источник: `scheduling_logistics_part_1_modules_01-05_v0.1 (1).md`, TRF-02—05 и TRF-17—18,
совместно с позднейшими CON-01—11 и регламентом менеджера. Это не новые решения владельца:

- Ровно 24 часа — своевременно; менее 24 часов — поздно.
- Два стандартных своевременных переноса одного оплаченного урока по инициативе ученика.
  Третий и следующие требуют решения директора. Глобального лимита разных уроков нет.
- Изменения по инициативе преподавателя/академии и согласованная заморозка этот счётчик
  не расходуют. Инициатор и причина сохраняются в Audit.
- Обычная поздняя отмена ученика списывает право, но не означает проведение урока.
  Исключение без списания требует отдельного решения директора.
- Компенсация преподавателю за позднюю отмену — отдельное обязательство. Списание ученику
  не создаёт фиктивный факт проведения и обычное преподавательское начисление.

Для старых уроков без достоверного инициатора прежних изменений история переносов не
угадывается: конкретное изменение ученика требует директорского исключения. Нулевой новый
счётчик не объявляется доказательством отсутствия исторических переносов.

Расширенный Meet API по REL-01/A остаётся в объёме MVP. Заглушка MGR-06 не является
реализацией API/OAuth/POC и не закрывает соответствующую приёмку. Применение миграций,
PostgreSQL-гонки и FND-GATE данным дополнением также не подтверждаются.
