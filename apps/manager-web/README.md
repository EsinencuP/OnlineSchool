# MGR-10 — кабинет менеджера

Визуальное обновление по `template/manager.webp` и материалам `ref/`:
тёмная навигация, рабочий dashboard с календарём, компактные списки,
быстрые действия, поиск портфолио и новая страница входа. Подробности —
`docs/online_academy_manager_reference_design_2026_11_01.md`.

01.11.2026. Реализованы срезы S1–S6. Проверки интерфейса используют OpenAPI/Orval
и MSW, не рабочую БД. Реальная приёмка на чистой БД и общий gate остаются открыты.

## Размещение и запуск

Кабинет ученика находится в `apps/student-cabinet`. Общего UI-пакета нет, поэтому
создан отдельный workspace `@online-school/manager-web`. Версии React 18.3.1,
Vite 7.3.7, Router 7.18.5, React Query 5.105.0 и Zustand 5.0.16 совпадают с учеником.
Формы используют нативные React/FormData и браузерную валидацию, как в Модуле 1.
Цвета, типографика и базовые размеры согласованы с существующим кабинетом.

```powershell
pnpm --filter @online-school/manager-web dev
# http://127.0.0.1:5177/manager/login
pnpm --filter @online-school/manager-web dev --mode mock
# Только локальные OpenAPI/MSW fixtures, без БД и внешней доставки
```

Обычный Vite проксирует `/api` на `127.0.0.1:3000`. Настоящие Secure `__Host-`
cookies и staff WebAuthn требуют существующего HTTPS origin и согласованных
настроек ядра. Локальный HTTP с моками не подтверждает настоящую MFA/аутентификацию.
Роли и авторизация остаются в Nest/core; административная имперсонация не введена.

Сборка Vercel копирует SPA в `apps/platform/dist/manager`; rewrites поддерживают
прямые ссылки `/manager/...`. Это подготовленная конфигурация, публикация не
выполнялась. `infra/vercel/build.mjs` также запускает миграции существующей среды:
для локальной проверки кабинета используйте только адресный `manager-web build`.

## Экраны

| Путь                            | Действия                                                                                                     |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `/manager`                      | Dashboard, временные горизонты, ссылки в очереди и карточки                                                  |
| `/manager/students`             | Поиск, статусы, просроченные/истекающие, сортировка, cursor, создание без аккаунта                           |
| `/manager/students/:id`         | Обзор, версии контактов, направления, абонементы, поступления/распределения, расписание, задачи, уведомления |
| `/manager/students/:id/account` | Создание после опубликованной оплаты; reset; отдельный однократный экран пароля                              |
| `/manager/schedule`             | День/неделя/список, назначение, перенос, отмена, Meet override                                               |
| `/manager/tasks` и `/:id`       | Фильтры/cursor, claim, решения переноса и оспаривания, CAS reload                                            |

Для форм добавлен защищённый `GET /api/v1/manager/options?studentId=...`:
имена учеников своего портфолио, действующие предметы/тарифы, направления и
назначенные преподаватели, финансовые периоды ученика. Нельзя вводить UUID вручную.
Без studentId возвращаются только общие справочники и имена своего портфолио;
контактов, финансов чужой семьи и учебных результатов в справочнике нет.
Чтение выполняется через core `runReadOnly`, scope общий с MGR-01. Миграция не нужна.

В Swagger исправлены типы nullable-контактов и integer-параметров страниц;
контракты и Orval перегенерированы. Даты финансовых периодов передаются ISO,
а подписи форматируются в timezone менеджера, включая границу суток.

## Денежные и директорские правила

- Деньги — строки, `Decimal` и `Intl` с `BigInt` для группировки; дробь до четырёх
  знаков сохраняется. Занятия и денежный остаток показываются отдельно.
- Менеджер регистрирует MDL-поступление и передаёт директору. Создание/продление
  используют готовый опубликованный distributionId; подготовка и доплаты находятся
  на вкладке платежей. Поступление по CRM-контакту не считается деньгами ученика.
- Заморозка 30/60, отмена пересекающихся уроков и отмена со списанием требуют
  явного согласия на последствия. Новые занятия/переносы сохраняют правило 60 минут.
- Поздний/третий перенос и ACCEPT оспаривания не выдаются за исполненное решение:
  показывается ожидание директора; частичная корректировка — отдельное Finance-решение.
- Ручное уведомление202 показывается QUEUED, затем обновляется фактический статус
  доставки. HTML пользователя не исполняется.

## Сессия, пароли и ошибки

API вызывается только через сгенерированные функции. Cookies `include`, CSRF через
`getCsrfToken`, `X-CSRF-Token`, UUID Idempotency-Key. Ключ создаётся при открытии
формы, сохраняется при retry, меняется после успеха или изменения команды.
Двойная отправка блокируется ref и disabled. Секретные ответы не используют
MutationCache; общий cache хранит только чтение.

Любой401 отменяет текущие запросы, очищает QueryCache/MutationCache и переводит
на вход. Выход очищает оба кэша и покидает приватный экран даже при сетевой ошибке;
ошибка завершения серверной сессии показывается на входе. 403 `/me` — «Нет доступа».

Пароль хранится только в локальном состоянии экрана, очищается при уходе/pagehide;
поздние ответы отменённой формы/сессии игнорируются. BFCache повторно загружает
экран. Нет localStorage/sessionStorage, секретов в URL, аналитики или логирования.
Копирование выполняется только по кнопке; пароли не входят в снимки/трассы проверок.

`ERROR_MESSAGES satisfies Record<AnyManagerErrorCode,string>` покрывает221 код из
генерируемого каталога backend/core. Новый код требует дополнить словарь при
следующей генерации. Технический backend message не показывается; requestId
сохраняется для поддержки. VERSION_CONFLICT/TASK_VERSION_CONFLICT открывают диалог
обновления версии без размонтирования формы и потери введённого текста.

## Проверка и границы доказательств

```powershell
pnpm --filter @online-school/manager-web build
pnpm --filter @online-school/manager-web lint
pnpm --filter @online-school/manager-web test
pnpm --filter @online-school/manager-web test:e2e
node scripts/mgr10-bundle-budget.mjs
```

14 Vitest/Testing Library проверок: платёж, заморозка, перенос, оспаривание,
точность денег, DST, CSRF, retry/конкурентная отправка, очистка кэшей/поздние ответы.
13 Playwright-проверок: СЦ-М-01…05, очередь доставки/Meet, ошибки/доступ, login→MFA,
секрет/выход, axe на экранах и диалоге, размеры360/768/1280. При директорских
решениях тест отдельно меняет состояние fixture: интерфейс менеджера их не исполняет.
MSW routes выводятся из OpenAPI, fixtures типизированы сгенерированными DTO;
MSW/worker и тестовые данные исключены из production bundle.

Начальный JS: около84.5 KiB gzip; dashboard с транзитивными импортами —142.3 KiB,
список учеников —143.3 KiB, ниже250 KiB. Скрипт проверяет manifest, статические
зависимости и отсутствие inline scripts/моков. Маршруты и вкладки загружаются лениво.
В CI добавлен отдельный job без БД с Vitest, Playwright/axe и проверкой бюджета.

Точные команды, результаты и хэши — `tests/evidence/mgr10-verification.json`;
браузерный отчёт, размеры и снимки без пароля — `output/mgr10/`.
Общие recursive проверки и реальная приёмка на чистой БД не объявляются пройденными:
действует `PHASE0_CHECKS.md`, одна рабочая Neon main, без отдельного PostgreSQL.
Реальный staff authenticator, PostgreSQL, внешняя доставка и deployment здесь
не проверялись. MGR-09 p95 и открытые migration/gate-условия остаются отдельными.

На Windows генераторы используют атомарную замену и пропускают неизменившиеся файлы,
чтобы открытый в редакторе/mapped OpenAPI не блокировал truncate. Orval пишет staging
`client.next.ts`, а script публикует `client.ts`; используйте `generate:client` package script.
