# Google Meet в расписании

Расширенный API входит в первый MVP по [REL-01/A](../../docs/platform-rules.md). Серверный клиент поддерживает создание пространства и проверку известного ресурса или кода встречи. В ответе стабильный идентификатор пространства отделён от ссылки для входа. Google допускает искать по коду и рекомендует хранить стабильный идентификатор для последующих обращений. [Документация spaces.get](https://developers.google.com/workspace/meet/api/reference/rest/v2/spaces/get)

## Подключение преподавателя

Маршруты `/api/v1/teacher/meet/oauth` работают для действующего преподавателя с проверенной MFA.

- `GET` возвращает доступность и состояние подключения без идентификатора Google и токена.
- `POST /start` выдаёт адрес согласия Google и срок действия. PKCE и одноразовый `state` связаны с сессией преподавателя.
- `POST /complete` принимает `code` и `state` после возврата с Google. Ту же сессию сервер проверяет перед обменом и перед сохранением. Клиентский маршрут возврата подключается с кабинетом.
- `POST /disconnect` прекращает использование подключения на платформе до обращения к Google. `REVOCATION_PENDING` означает, что отзыв ещё требует сверки. Повтор этого запроса позволяет возобновить отзыв после истечения 30-секундной блокировки.

При деактивации преподавателя платформа отзывает незавершённый OAuth-запрос, отключает сохранённое подключение и ставит отзыв токена Google в очередь. Повторный найм требует нового согласия Google. Запоздалое событие может отозвать только прежнюю версию подключения.

OAuth запрашивает `openid` для устойчивой привязки к учётной записи и `meetings.space.created` для чтения и создания пространств от имени преподавателя. Refresh-токен и PKCE хранятся зашифрованными. Для развёртывания нужны параметры `GOOGLE_MEET_*` из `.env.example`. В `GOOGLE_MEET_TOKEN_KEYS` задаётся JSON-объект с 32-байтовыми ключами в base64url. При ротации предыдущие ключи нужны для чтения уже сохранённых данных. [Google Meet OAuth](https://developers.google.com/workspace/meet/api/guides/authenticate-authorize) · [Google OAuth для серверных приложений](https://developers.google.com/identity/protocols/oauth2/web-server)

## Живая проверка Google

Используются два разных тестовых аккаунта Google с разрешением для проверяемого OAuth-клиента. Оператор фиксирует редакцию Workspace и выданные scopes для каждого результата. Краткоживущие тестовые токены передаются процессу в `MEET_POC_OWNER_ACCESS_TOKEN` и `MEET_POC_OTHER_ACCESS_TOKEN`.

~~~powershell
pnpm --filter @online-school/api build
pnpm --filter @online-school/api meet:poc --create-test-space
~~~

Режим `--create-test-space` один раз запрашивает создание тестового пространства, затем проверяет чтение владельцем и вторым аккаунтом. Для чтения уже подготовленного пространства задайте `MEET_POC_RESOURCE_NAME` и используйте `--inspect-test-space`. Переменная `MEET_POC_MANUAL_CODE` добавляет сверку вручную полученного кода. Вывод содержит результат операций и настройки приватности, без токенов, ссылок или идентификаторов ресурса. Неизвестный исход создания требует отдельной сверки и осознанного решения перед новым созданием.

## Создание и сверка пространства

Преподаватель управляет ссылкой своей пары через `/api/v1/teacher/assignments/:assignmentId/meet`. GET показывает опубликованную ссылку и состояние операции. POST `/create`, `/verify` и `/reconcile` требуют CSRF и ключ идемпотентности. Ответ `202` означает, что операция записана, а состояние Google появится после обработки.

Worker фиксирует отправку в PostgreSQL до внешнего запроса. Если после этого результат создания неизвестен или истекла аренда, запись остаётся доступной для сверки и в CRM создаётся внутренняя задача. Запросы проверки можно повторять в пределах политики worker. При ограничении квоты worker учитывает `Retry-After`. В outbox и CRM-задаче сохраняются идентификатор операции и код диагностики.

Если преподаватель нашёл ссылку на созданное пространство, `/reconcile` проверяет её из того же Google-аккаунта и связывает результат с исходной попыткой. Если внешняя сверка подтвердила отсутствие пространства, руководитель с MFA фиксирует основание через `/api/v1/director/meet/operations/:id/close-without-space`. Только после такого решения преподаватель может снова запросить создание. Руководитель может снять старую ссылку для будущих уроков через `/api/v1/director/meet/spaces/:id/retire`. История старых версий сохраняется.

Подтверждённая ссылка относится к паре «ученик–преподаватель» и применяется с момента публикации к регулярным урокам. Явная ссылка или явное снятие ссылки отдельного урока имеют приоритет. При отсутствии опубликованной ссылки остаётся ручная ссылка назначения. Действующие права ученика и окно входа за десять минут проверяются прежним способом.

Локальные тесты используют подменённые ответы Google. Живая проверка OAuth/Workspace и приёмка G4, а также проверка миграций и восстановления аренды на PostgreSQL остаются открыты.
