# STU-09 — образовательные отчёты и PDF-выписка

Статус на 2026-10-28: код и целевые проверки готовы. Владелец выбрал завершение
с отложенной PostgreSQL-проверкой. Миграции в рабочую БД и деплой не выполнялись;
реальные PostgreSQL/S3 и сквозная доставка PDF ещё не проверены.

## API

Все четыре маршрута используют существующие session/STUDENT/context/password/
active-access guards STU-01. `studentProfileId` берётся из серверной сессии.
Ответы приватные (`Cache-Control: no-store`). Ученических команд создания или
редактирования образовательного отчёта нет.

| Маршрут                                          | Поведение                                                                                                         |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `GET /api/v1/student/reports?page=1&pageSize=10` | Опубликованные отчёты, `createdAt DESC, reportId DESC`; pageSize 1–100; items/total/page/pageSize                 |
| `POST /api/v1/student/reports/:reportId/read`    | Пустое тело; первый вызов 204, повторный 200 с пустым телом, включая replay того же ключа; isNew становится false |
| `POST /api/v1/student/reports/export-pdf`        | 202, `{jobId,status:'QUEUED',estimatedReadyAt}`; пустое тело означает всю историю                                 |
| `GET /api/v1/student/reports/export-pdf/:jobId`  | QUEUED/PROCESSING/READY/FAILED; чужое или неизвестное задание — 403                                               |

POST требуют CSRF и UUID `Idempotency-Key`. Read receipt и задание создаются
атомарно с idempotency/audit/outbox. Повторная команда не ставит дубликат задания;
после отзыва доступа replay также закрыт существующими guards.
SDK использует отдельный mutator для пустых ответов read; остальные JSON-операции
продолжают отвергать неожиданный пустой успешный ответ.

Необязательное тело экспорта: `{subjectId?,periodFrom?,periodTo?}`. Даты строго
YYYY-MM-DD, границы включительны по часовому поясу ученика, включая DST. Чужой
предмет — 403. Не более двух незавершённых заданий на ученика (иначе 429).
Оценка готовности +30 секунд — ориентир. Клиент может опрашивать каждые 2 секунды
до 60 секунд, затем вернуться к тому же заданию позже; тайм-аут клиента его не отменяет.

## Какие данные видит ученик

Только LESSON_8, PUBLISHED и публикации не из будущего. Для каждой контрольной
точки выбирается последняя опубликованная версия; черновик исправления не скрывает
предыдущую публикацию. Read receipt относится к конкретной версии.
`createdAt` — фактическая дата создания. `periodFrom/To` — календарные даты.
Публичное содержимое ограничено achievements/growthAreas/recommendations/
teacherSignature; внутренние JSON-поля и заметки учителя исключены.

Подготовленный publication guard допускает действующего назначенного учителя,
четыре текстовых поля и ровно восемь подтверждённых CONDUCTED уроков предмета
за период, включая перезачисления. При публикации сохраняется count snapshot=8.
Для старых публикаций без snapshot количество подтверждается запросом; неправильный
период не выдаётся за восемь уроков. Публикации сохраняют прежнюю неизменяемость.
Учительские команды, автоматическое создание контрольных точек и срок подготовки
отчёта за три рабочих дня относятся к будущему teacher workflow; STU-09 их не закрывает.

PDF включает имя ученика, период и дату; текущую карту навыков и цели STU-08
на `source_as_of`; все опубликованные отчёты выбранной истории с четырьмя полями
и подписью; посещения с датами, предметом, учителем и статусом. При фильтре дат
пересекающий период отчёт включается целиком, посещения фильтруются по датам,
карта навыков остаётся текущей и явно датирована. Будущие уроки исключены;
пропуск выводится только из подтверждённого факта student_no_show, прочие отмены
не превращаются в пропуски. Доступ не ограничен текущим абонементом.
Автоматических внешних уведомлений семье нет (CON-08/B).

## Воркер, приватный объект и срок ссылки

`JobRecord` с типом `student.education-pdf.generate.v1` и принадлежащий ученику
`PdfExportJob` создаются одной транзакцией. Отдельная очередь БД использует
SKIP LOCKED, committed claim, lease 120 секунд, fenced attempt UUID, максимум
три попытки с backoff. PDF обрабатывается одним фоновым заданием на процесс
параллельно обычному poll: finance/schedule/outbox не ждут рендер PDF.
Остановка прерывает рендер и дожидается завершения активной обработки.

Перед фиксацией источника и публикацией результата заново проверяется активный
владелец. Источник состоит из публичных проекций, сохраняется один раз и повторно
используется при retry. Рендер и S3 I/O выполняются вне транзакции. Проверка lease
получает свежее время после блокировки строки. Просроченная попытка не публикуется.
Deferred constraints требуют атомарного SUCCEEDED + READY.

PDFKit использует локальные Noto Sans Regular/Bold (OFL), включённые явно в
Docker allowlist; системные шрифты и Chromium не нужны. Ограничения: 60 секунд
на рендер, 20 MiB и 1000 страниц; превышение заканчивается FAILED без обрезания истории.
Файлы шрифтов, источники и лицензия — `apps/worker/assets/fonts/`.

Объект приватный, ключ `student-exports/<job UUID>/<attempt UUID>.pdf`,
Content-Type application/pdf, no-store; create-only PUT (`If-None-Match: *`).
Неоднозначный ответ PUT сверяется по HEAD/размеру/hash. Повтор не перезаписывает
готовый файл. При потере подтверждения DB commit объект сначала сверяется с
сохранённым результатом, чтобы не удалить уже выданный PDF. Неопределённые orphan
объекты сохраняются до отдельной retention-процедуры; lifecycle/retention необходимо
закрепить при настройке реального S3. Signed URL не хранится в БД или idempotency.

При READY ссылка подписывается от фиксированного `ready_at` на 3600 секунд;
повторный polling не продлевает срок. `expires_at=ready_at+1 hour`.
На самой границе истечения API возвращает FAILED/PDF_EXPORT_EXPIRED без ссылки;
для новой ссылки нужен новый экспорт. Обычные private upload ссылки на 900 секунд
не изменены. Реальный провайдер должен поддерживать SigV4/3600 секунд и приватный
bucket; инфраструктурная политика или временные credentials могут сократить срок.
Ошибки API содержат безопасный код без S3/SQL/личных данных.

## Проверки и оставшаяся приёмка

`pnpm test:stu09` — 81 целевая проверка с mock Prisma/S3, включая настоящий
Nest HTTP/session/CSRF/idempotency pipeline, rollback, ownership, retry/fencing,
отзыв доступа, фиксированное истечение с мокированным временем и generated SDK.
Дополнительно прошли две существующие transport-проверки. Настоящий PDF рендерится
командой `node tests/support/render-education-pdf-sample.mjs` после worker build;
образец полностью синтетический, три A4 страницы визуально проверены.

Миграция `20261027170000_stu09_reports_pdf` подготовлена после STU-01–08.
Prisma validate/generate, API/worker/SDK builds и целевой lint прошли.
24 SQL statements, четыре PLpgSQL-функции и десять source-exact SELECT fixture
сценариев разобраны офлайн через libpg_query/pglast; это не проверка SQL binding,
прав, блокировок, триггеров и фактического исполнения.
Read-only сценарий `tests/integration/student-reports-readonly.test.mjs` подготовлен
для PostgreSQL 18; по решению владельца он не запускался. Он не заменяет будущую
проверку write constraints, конкурентных worker claims и реального S3 download/expiry.

Результаты: `infra/STU09_EVIDENCE.json`, `tests/evidence/stu09-sql-syntax.json`,
`tests/evidence/stu09-pdf-review.json`. Проверка рабочей среды, применение миграций,
сквозной экспорт через S3 и FND-GATE остаются открытыми. Дополнительные БД,
ветки Neon и контейнеры не создавались; Docker image и полная регрессия не запускались.
