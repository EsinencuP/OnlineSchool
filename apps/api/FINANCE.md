# TASK-08 — Finance

Реализованы 17 HTTP-операций Finance. Все требуют серверной сессии и завершённого
MFA; POST дополнительно требуют CSRF и UUID `Idempotency-Key`. Права и назначение
менеджера повторно проверяются внутри SERIALIZABLE-транзакции, включая возврат
кэшированного результата. Бизнес-записи, AuditEvent, OutboxEvent и результат команды
фиксируются атомарно. Отказ обязательного аудита отменяет также проводку и CRM-задачу.

Это локальная реализация по утверждённым требованиям, без production GO/FND-GATE.
Канонические решения: [CON-01—11](../../docs/online_academy_CON_01_11_owner_decisions_addendum_v1.0.md).

## Маршруты и доступ

Префикс `/api/v1`. DIRECTOR имеет доступ ко всем перечисленным командам. MANAGER
работает только с назначенным учеником; распределение проверяет также доступ к
контакту платежа. Household сам по себе не предоставляет финансовых полномочий.

| Метод и маршрут                | Дополнительный доступ           | Тело запроса                                                        |
| ------------------------------ | ------------------------------- | ------------------------------------------------------------------- |
| POST payments/register         | MANAGER                         | studentId, amount, currency; provider + externalReference вместе    |
| POST payments/:id/confirm      | Только DIRECTOR                 | {}                                                                  |
| POST payments/:id/distribute   | MANAGER                         | subscriptionId, amount                                              |
| POST distributions/:id/approve | Только DIRECTOR                 | {}                                                                  |
| POST subscriptions             | MANAGER                         | enrollmentId, saleConditionId                                       |
| POST entitlements/grant        | MANAGER                         | subscriptionId, distributionId; quantity необязательно              |
| POST entitlements/consume      | MANAGER                         | grantId, studentId, lessonId; reason необязательно                  |
| POST entitlements/adjust       | Только DIRECTOR                 | grantId, kind, reason; originalConsumptionId, deltaQuantity по виду |
| POST temporary-access          | Только DIRECTOR                 | subscriptionId, grantedLessonsCount, expiresAt, basis               |
| POST ledger/entries            | Только DIRECTOR                 | documentId **или** entryId; periodId, lines необязательно           |
| POST ledger/adjustments        | Только DIRECTOR                 | entryId, reason; periodId, replacementLines необязательно           |
| GET periods                    | MANAGER                         | Последние 100 периодов                                              |
| POST periods/:id/close         | Только DIRECTOR                 | {}                                                                  |
| POST accruals                  | MANAGER                         | outcomeId, basis; exceptionAmount только DIRECTOR                   |
| POST payouts/attempt           | MANAGER                         | obligationId, amount, provider, providerRequestId                   |
| POST payouts/:id/confirm       | MANAGER                         | providerConfirmationId; amount необязательно                        |
| GET teacher/:id/payroll        | TEACHER — только своя ведомость | Последние 100 начислений                                            |

TECH_OPERATOR финансовых прав не имеет. Teacher получает начисления и подтверждённые
выплаты, без стоимости ученических абонементов и маржи. Прямое создание платежа не
выдаёт права, доступ или StudentAccount. PaymentReceipt.status в ответе вычисляется
как REGISTERED/CONFIRMED по неизменяемому факту подтверждения директора.

Точные DTO и ответы: [OpenAPI](../../packages/api-contracts/openapi/openapi.json).
Деньги передаются **строками**, например `"100.0000"`: до 16 целых и 4 дробных знаков.
JSON number, экспонента, отрицательная сумма и лишняя точность отклоняются. Ноль
допускается только как явное индивидуальное решение директора по начислению.

## Платежи, права и допуск

Регистрация, подтверждение поступления, предложение и утверждение распределения —
разные факты. Подтверждение создаёт внутреннюю CRM-задачу с настоящим source_event_id;
уведомлений семье не отправляет. Цена, скидка и цена урока копируются сервером из
SaleCondition. Если деление цены на уроки не сходится точно, требуется отдельная
проверка условий продажи; новый метод округления не вводится.

EntitlementGrant разрешён после полной совокупной подтверждённой распределённой
оплаты абонемента. Выдача ограничена исходным количеством уроков. Каждая неполная
оплата/рассрочка требует отдельного ограниченного решения директора (CON-02/B).
TemporaryAccessPermission хранит лимит, срок, директора и основание; платного grant
не создаёт. После полной оплаты выдаются обычные права без дублирования.

Grant остаётся исторической записью. Остаток вычисляется как quantity + корректировки
− действующие списания; отдельного изменяемого remaining_count в таблице нет.
Списание блокирует grant, проверяет ученика/предмет, CONDUCTED + подтверждённый outcome,
открытый период урока. SQL UNIQUE защищает пару lesson/subscription; trigger запрещает
отрицательный остаток, включая разные параллельные уроки. Повтор одного урока даёт
409, исчерпание прав — 422. Корректировка требует директора и причины; положительная
GRANT_DELTA требует ссылки на исходное списание. Отмена списания в открытом периоде
сохраняет исходную запись и публикует отдельный reversal выручки.

## Проводки и закрытые периоды

Публикация проверяет точные агрегаты DEBIT/CREDIT **по каждой валюте**. SQL дополнительно
проверяет баланс и защищает опубликованные строки и заголовки от изменения/удаления.
Для приложения используется роль с правами `online_school_runtime`, для миграций —
отдельная direct connection. UPDATE(id) immutable grant разрешён только ради
PostgreSQL FOR UPDATE; существующий trigger по-прежнему запрещает UPDATE самой записи.
HR-основания этой роли доступны только на чтение, AuditEvent — без UPDATE/DELETE.

Автоматические проводки создаются в транзакции исходной команды:

| Факт                           | DEBIT             | CREDIT            |
| ------------------------------ | ----------------- | ----------------- |
| Подтверждение поступления      | CASH              | UNALLOCATED_FUNDS |
| Утверждение распределения      | UNALLOCATED_FUNDS | CUSTOMER_ADVANCE  |
| Оплаченный подтверждённый урок | CUSTOMER_ADVANCE  | LESSON_REVENUE    |
| Признание начисления           | TEACHER_EXPENSE   | TEACHER_PAYABLE   |
| Подтверждение выплаты          | TEACHER_PAYABLE   | CASH              |

`ledger/entries` публикует существующее разрешённое основание; переданные строки
должны совпадать с его канонической суммой и счетами. Произвольной сбалансированной
проводкой нельзя создать деньги или долг. Несбалансированный ввод даёт 422.

`ledger/adjustments` исправляет ошибочную классификацию исходного опубликованного
факта: полный reversal + каноническая замена в текущем открытом периоде. Оригинал,
его дата и закрытый период остаются неизменными. Повторный reversal запрещён UNIQUE;
повторная сложная цепочка и изменение финансового основания требуют отдельного
регламента. Это не реализация возвратов, банковских операций или новой refund-методики.
Методика 11.3.2/A сохранена, юридические детали/округление/автоматизация возвратов
и формальное закрытие экономики 11.4 остаются открытыми.

Период закрывает директор после окончания его срока. Draft-проводки, disputed либо
неполные conducted-факты/начисления, pending/UNKNOWN выплаты блокируют закрытие.

## Ставки и выплаты

Обычная ставка: min(6, floor(eligibleMonths/2)) + min(4, floor(activeStudents/2)).
0–4 очка → 200 MDL, 5–9 → 220, 10 → 250. Автоматической ступени 230 или добавок
+20/+30 нет. Ранее индивидуально обещанные обязательства не отменяются: отдельная
TeacherRatePromise с основанием и директором явно задаёт минимум и/или добавку.
Поэтому **явно обещанные** 230 допустимы, автоматические обычные 230 — нет.

TeacherEngagement хранит периоды работы, TeacherTenureCredit — подтверждённые полные
календарные месяцы без неучитываемых пауз. HR-оператор с отдельными maintenance-правами
вносит проверенные основания с директором; финансовый HTTP не принимает KPI от клиента.
Частичные месяцы не округляются в стаж новым неутверждённым способом. Возвращение
включает предыдущую цепочку стажа только при каждом перерыве ≤ 6 календарных месяцев;
через 7 месяцев прежние credits не учитываются. Считаются уникальные оплаченные активные
ученики/оплаченные заморозки с остатком прав, без временного неоплаченного допуска.

`TeacherRateService.snapshotAtStart(ctx, lessonId, teacherId, time)` экспортирован для
команды фактического начала TASK-09. Вызывать только внутри критической транзакции
с серверным/доверенно подтверждённым временем; отдельного HTTP для подмены времени нет.
Сервис сохраняет ставку, очки, валюту, вид основания и evidence на фактический старт.
Изменение влияет на следующий подходящий урок сразу, без ожидания первого числа;
существующий snapshot защищён SQL. Начисление использует outcome, не пересчитывает
прошлую ставку и не вводит неподтверждённую поминутную пропорцию.

Неоплаченный проведённый урок не превращается автоматически в нулевую оплату или
долг: требуется явный exceptionAmount директора с основанием. Snapshot сохраняется
отдельно от индивидуально разрешённой суммы. Начисление создаёт PayrollObligation;
попытка выплаты не считается подтверждённой выплатой. Pending/UNKNOWN резервируют
обязательство и блокируют повторную попытку; UNKNOWN нельзя слепо подтвердить.
Подтверждение требует ссылки на проверенное свидетельство. Реального банковского
перевода, API банка или автоматического reconciliation здесь нет.

## Worker и проверка

Worker раз в секунду выбирает только `finance.temporary-access.expire.v1`, используя
FOR UPDATE SKIP LOCKED, lease 30 секунд и не более трёх попыток. По истечении допуска
он атомарно создаёт одну внутреннюю CRM-задачу текущему менеджеру, Audit и Outbox;
права не продлевает. Повторная обработка не дублирует задачу. Общий outbox dispatcher
и внешние интеграции остаются TASK-11.

Новая четвёртая migration `20261026050000_task08_finance` добавляет три HR-модели,
источники ledger, необходимые FK/UNIQUE/SQL-защиты и минимальные runtime-права.
Прежние миграции сохранены. До upgrade preflight отклоняет двойные reversal;
исправление старых данных автоматически не выполняется.

```sh
pnpm install --frozen-lockfile
pnpm -r typecheck
pnpm -r build
pnpm -r lint
pnpm test
# Три отдельные migrated localhost БД online_school_test*:
# TEST_DATABASE_URL, IDENTITY_TEST_DATABASE_URL, FINANCE_TEST_DATABASE_URL
pnpm --filter @online-school/api test:integration
# Отдельная reference-seeded TEST_DATABASE_URL для DB-регрессии:
pnpm --filter @online-school/db test:integration
# Отдельная QA_DATABASE_URL online_school_qa*:
pnpm --filter @online-school/db test:qa
```

Три новых unit-теста проверяют границы очков/ставок, шестимесячный возврат и точность
денег. Четырнадцать Finance HTTP/PG тестов работают под настоящей ограниченной
runtime-ролью: права, idempotency, конкурентное списание, reversal, полная/частичная
оплата, неизвестная выплата, атомарный откат при отказе Audit, неизменность snapshot
и самостоятельная обработка worker. Синтетические данные; реальные платежи не создаются.
