# STU-12 — кабинет ученика

28 октября 2026. Реализован React/Vite SPA в отдельном workspace. Статус:
**код и адресные проверки выполнены; рабочая приёмка, STUDENT-GATE и FND-GATE открыты**.
Рабочая Neon main, миграции и S3 этой задачей не изменялись; публикация не выполнялась.

## Запуск и проверка

```powershell
pnpm --filter @online-school/api build
pnpm --filter @online-school/api start
# В другом терминале:
pnpm --filter @online-school/student-cabinet dev
# http://127.0.0.1:5174/student/login
```

Vite проксирует `/api` на `127.0.0.1:3000`. Для настоящих `__Host-` cookies нужен
действующий HTTPS origin и существующая конфигурация API. Локальный HTTP не
объявляется рабочим стендом аутентификации. Dev-прокси QA-оболочки `/student`
направлен на порт 5174. Вход ученика через прежнюю оболочку переводит в `/student`.

```powershell
pnpm --filter @online-school/student-cabinet build
pnpm --filter @online-school/student-cabinet lint
pnpm test:stu12
pnpm test:stu12:a11y
```

Браузерные команды сами собирают только кабинет. Playwright/Chromium должен быть
установлен (`pnpm exec playwright install chromium`, если отсутствует). Tests используют
отдельный **локальный синтетический HTTP fixture**, не PostgreSQL/Neon/S3. Он запускается
только командой проверки и не включается в bundle. Cookies fixture не являются рабочими
учётными данными. При проверке загрузки реальный fetch PUT перехватывается Playwright.

Существующая сборка Vercel собирает API, QA-оболочку и кабинет, копирует кабинет в
`apps/qa-shell/dist/student`. Корневые rewrites сохраняют прямые `/student/...` ссылки.
Это подготовленная конфигурация: запуск build.mjs применяет рабочие миграции, поэтому
для проверки фронтенда его запускать нельзя. В этой задаче проверены отдельные SPA build.

## Экраны и контракты

Все 13 маршрутов задания и дополнительный `/student/login` реализованы. Router в
`src/router.tsx`; общий layout — `src/Layout.tsx`; экраны сгруппированы в `src/pages/`.

- Desktop: 240 px слева, центр, 320 px справа. Tablet: меню по кнопке, справа календарь;
  остальные виджеты внутри страницы. Mobile: пять кнопок снизу, полное меню в modal
  dialog, календарь/абонемент/материалы/контакты в раскрываемом блоке страницы.
- Dashboard: четыре карточки из настоящего `getStudentDashboard`, пять ближайших
  уроков, три последних ДЗ, первый предмет карты навыков. Таймер не выдаёт права
  подключения: только серверные `canJoin` и проверенный Meet URL. В момент границы
  десяти минут выполняется refetch; дополнительно расписание опрашивается каждые 30 с.
- Lessons: четыре периода, постраничный список и календарный режим с выбором месяца.
  Перенос отправляет reason/preferredDate в существующую CRM-команду, не меняет расписание.
- Homework: фильтр статуса, описание, версии от старой к новой, комментарии и поздняя
  сдача. Draft debounce 2 с, сериализация сохранений, восстановление с сервера,
  предупреждение при уходе с несохранённым текстом. Авторизационные перенаправления
  не блокируются предупреждением. Сдача ждёт ранее начатого сохранения.
- Файлы: upload-url → прямой PUT без cookies/CSRF → confirm → fileIds при submit.
  Успешный PUT не повторяется при повторном confirm. Ключи upload/confirm/submit
  сохраняются для повторной попытки того же намерения после ошибки. Новая правка
  черновика получает новый ключ. Сервер остаётся окончательным валидатором файлов.
- Skills: четыре качественных статуса, предметы, цели, история изменений навыка
  и подтверждённых срезов. Абонемент показывает подтверждённые занятия, платежи
  Decimal без преобразования в float, историю баланса; платёжных действий нет.
- Notifications: individual-read/read-all с обновлением обоих счётчиков. Profile:
  display alias; Security: пароль, email OTP и завершение других активных сессий.
- Публичный suspended: только сообщение/доступные контакты назначенного менеджера;
  если сессии нет, персональные контакты недоступны, навигация не появляется.

TanStack Query v5 хранит server state, Zustand — только глобальное состояние меню.
Транспорт использует сгенерированный SDK, same-origin session, CSRF и UUID-команды.
Автоматических повторов mutations нет. 402 ведёт в suspended, MUST_CHANGE_PASSWORD
в ответе/ошибке — на смену пароля, истёкшая сессия — на вход. Неверный текущий
пароль не считается истёкшей сессией. Query cache очищается при смене доступа/выходе.
Дата и время используют IANA timeZone, полученный от API.

Для прямых ссылок и ближайших уроков добавлены небольшие read-only API-проекции:

| Метод | Маршрут                             | Поведение                                                                  |
| ----- | ----------------------------------- | -------------------------------------------------------------------------- |
| GET   | `/api/v1/student/lessons/upcoming`  | Следующие пять ещё не завершившихся SCHEDULED, без границы месяца          |
| GET   | `/api/v1/student/lessons/:lessonId` | Один собственный урок, независимо от периода                               |
| GET   | `/api/v1/student/homework/:hwId`    | Одно собственное видимое ДЗ с версиями                                     |
| GET   | `/api/v1/student/me`                | Дополнен timeZone и безопасными контактами менеджера для активного ученика |

Detail-фильтры параметризованы и соединены с student ownership до pagination.
Чужой и отсутствующий UUID одинаково возвращают 404. Существующие guards initial
password/active access сохраняются. OpenAPI/SDK перегенерированы. Миграций нет.

## Проверки и ограничения

Подтверждены сборки кабинета и QA-оболочки, адресный ESLint, 157 unit/HTTP проверок
контекста, bootstrap и затронутых lesson/homework контрактов (mock Prisma), 12
браузерных сценариев. Результаты: `output/stu12/playwright.json`, `desktop.png`,
`mobile.png`. Lighthouse 13.6.0: **100 Accessibility на всех 14 маршрутах**,
desktop 1600×1000, production bundle с синтетическим API; результат в
`output/stu12/accessibility.json`. Playwright отдельно проверяет отсутствие
горизонтального переполнения всех страниц на 360 px, layout 390/820/1600 px,
диалоги, серверные ошибки и повторы. Это не аудит доступности всех возможных данных.

Рабочий E2E с настоящей сессией, применёнными STU-миграциями и S3 upload, настоящая
доставка email OTP и ручная приёмка остаются открыты. Общий recursive/regression
прогон не запускался согласно PHASE0_CHECKS.md. Результаты прошлых этапов не
объявляются текущим gate.

Ограничения существующих API: вложения ДЗ доступны как метаданные, отдельного
контракта скачивания всех homework attachments нет; не выдаём им выдуманные URLs.
Скачивание явно выданных материалов работает через существующий signed-url API.
Предварительный upload аватара также не имеет отдельного profile-контракта;
фронтенд не предлагает неработающую загрузку фотографии. Список подтверждённых
файлов до submit хранится в памяти страницы; сервер восстанавливает текст черновика,
но не список ещё не отправленных fileIds.

Визуальные источники и ограничения их интерпретации — в `PR_DESCRIPTION.md`.
