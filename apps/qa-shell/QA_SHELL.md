# TASK-12 — оболочка проверки рабочего проекта

React 18.3.1 + Vite 7.3.7. Постоянный адрес, выбранный владельцем:
https://onlineschool-xi.vercel.app. Используется единственный рабочий проект Vercel
`onlineschool`, единственная БД Neon `onlineschool` / `main` / `online_school`
(Frankfurt, PostgreSQL 18.6, организация lilDekim). Отдельного QA-проекта или shadow branch нет.

## Поведение

- Пароль создаёт ограниченную сессию. До WebAuthn нет бизнес-кнопок; API требует MFA.
- Регистрация passkey не завершает MFA. Аутентификация обновляет session/CSRF.
  Первый ключ регистрируется пользователем после доверенного назначения пароля.
- Все команды используют SDK, сгенерированный из настоящего OpenAPI TASK-10.
  Same-origin Secure/HttpOnly cookies; свежий `X-CSRF-Token` на каждую мутацию.
  Для бизнес-команд — `crypto.randomUUID()`. Неизменённый повтор в открытой форме
  сохраняет ключ; после успеха форма заблокирована до явной новой команды.
- Директор подтверждает платежи/распределения и публикует проводки. Менеджер этих
  кнопок не видит. API независимо проверяет роли, назначения и предметный контекст.
- Абонемент → предложение распределения → отдельное одобрение → выдача права:
  каждый шаг — реальная отдельная команда. API не выдаёт право при неполной оплате.
- Бронирование, сообщение исхода и списание — отдельные команды существующего API.
  Для списания требуется заранее подтверждённый факт; оболочка не создаёт его скрыто.
- Файловая проверка читает действующее разрешение текущего аккаунта, не выдаёт URL.
  Отозванный, чужой, просроченный или неверифицированный объект получает 403.
- `/api/docs` открывает Swagger. Статус API берётся из `/health`, БД/worker/миграция —
  из `/api/v1/qa/components` после MFA. Heartbeat показывает живой процесс, а не
  готовность очереди/релиза. Отсутствие worker отображается явно.
- Цвета и шрифты заданы CSS-токенами. Секции появляются за 200 ms; reduced-motion
  отключает анимацию. Проверены desktop 1440, tablet 768 и mobile 390 без overflow.

## Сборка и запуск

```sh
pnpm --filter @online-school/api build
pnpm --filter @online-school/qa-shell build
pnpm --filter @online-school/qa-shell dev
```

Dev proxy направляет `/api` и `/health` на API:3000 без удаления `/api` из пути.
Для настоящих Secure cookies и WebAuthn браузеру нужен HTTPS. Публичная сборка
содержит версию пакета, время, ожидаемую миграцию и переданный commit SHA.
Без Git/BUILD_COMMIT_SHA поле SHA честно сообщает об отсутствии; SHA не выдумывается.
Применённая версия миграции читается отдельно из БД через ограниченную SQL-функцию.

Vercel root directory: `apps/qa-shell`, включены исходники workspace вне корня.
`api/handler.ts` использует скомпилированный NestJS, кэширует HTTP application на
инстанс и не запускает polling worker. Сборка не применяет миграции и не создаёт аккаунты.

Server-only конфигурация: `DATABASE_URL`, `CSRF_SIGNING_SECRET`,
`WEBAUTHN_RP_ID=onlineschool-xi.vercel.app`,
`WEBAUTHN_ALLOWED_ORIGIN=https://onlineschool-xi.vercel.app`.
VITE_* секретов нет. Runtime использует ограниченную роль `app_runtime`,
не migration owner. `DIRECT_URL` хранится отдельно для maintenance и не передан Function.

`scripts/provision-initial-project.mjs` — одноразовая доверенная maintenance-операция
для пустого реестра аккаунтов. Создаёт обычного директора с audit, без MFA bypass.
Пароль и connection strings генерируются в игнорируемой `.identity-ops/`, не входят
в исходники публикации. Повтор не меняет существующий пароль, роли или MFA.

## Адресная проверка TASK-12, 27.10.2026

Локально: реальный PostgreSQL 18.6 + NestJS + собранный SPA; Chromium virtual CTAP2,
HTTPS origin локально направлялся в fixture server. Проверены пароль → ограничение
→ регистрация → отдельная MFA для директора, менеджера и преподавателя; различия
кнопок и серверный 403 для manager confirm. Через UI выполнены регистрация платежа,
подтверждение, создание абонемента, распределение, одобрение и grant. Повтор платежа
вернул тот же результат, в SQL осталась одна запись. Проверка файла: 200 → revoke
maintenance fixture → 403. Heartbeat в этом fixture — отдельный тестовый emitter.

На опубликованном HTTPS сайте, без локального перехвата: пароль, ограниченная стадия,
регистрация passkey и MFA временного обычного TEACHER, получение реальной версии
миграции Neon; API/DB ok, worker unknown. Повтор команды по несуществующему уроку
передал CSRF и тот же UUID Idempotency-Key; сервер отказал без бизнес-записи.
Swagger вернул 200. Временный аккаунт после smoke отключается, ключ и сессии
отзываются с audit. Ключ владельца регистрирует сам владелец.

Адресные build, ESLint и unit проверки точного WebAuthn origin пройдены.
Идентификатор финального deployment и SHA-256 применённых миграций записаны в
`TASK12_EVIDENCE.json`. Отдельный read-only скрипт сверил все семь checksums с SQL-файлами.
Полный регрессионный прогон, CI, опубликованный worker и FND-GATE здесь не объявляются
пройденными: это последующие TASK-13—15. Ручная приёмка владельцем/QA остаётся отдельной.
