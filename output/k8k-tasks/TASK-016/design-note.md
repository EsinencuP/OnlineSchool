# TASK-016 — design note

Общий display contract в packages/ui: errorMessageKeys (существующие wire codes → typed dictionary keys), describeError(error, operation) → key/severity/nextAction/outcome/fields, errorText(error, locale), ErrorFeedback(error, retryRead?, amount?) и ErrorForm(error, ...formProps) с useFieldError(name). Одна RU/RO пара в messages.ts, без locale store или SDK в UI. ERROR_MESSAGES менеджера остаётся RU-совместимым derived export. Raw message/detail/requestId/IDs не выводятся. details.fields принимаются только как имена существующих полей, не как тексты сообщений. amount для пояснения — только собственная введённая decimal string, через существующий formatMoneyAmount.

ClientError сохраняет status/code/message/existingId и получает optional details от уже существующего error response. Серверный контракт/DTO/operations не меняются, generated не редактируется. Student problem response не передаёт произвольные details; для известных ошибок безопасные имена полей определяются display adapter по code. ClientError детали не копируются в строки UI.

ApiErrorView получает optional operation/read|write; errorView сохраняет wire code/status, совместимое безопасное RU message и details. Unknown write (network/5xx/invalid response/in-progress) предлагает сверку результата без retry. Hook guards блокируют повтор неизвестного действия до новой сверки/перезагрузки. Студенческая очередь autosave и useIntentKey сохраняются. CURRENT_PASSWORD_INVALID и INVALID_CREDENTIALS при записи не вызывают общий 401 logout. Обычный 401 продолжает отзыв контекста, object 403 скрывает cached body без безусловного logout.
Адресный бюджет обнаружил лишнюю eager-зависимость: резюме балансов в Student тянуло Decimal в календарную вкладку, а бизнес-формы тянули тот же форматтер ради input validation. Планируется BalanceSummary({ balances: StudentCardDto["balances"] }) в существующем Suspense и money-validation.ts с прежним regex/точной проверкой положительного decimal input. Money formatter/Decimal, данные и команды сохраняются. Для overview в бюджетном плане добавляется его явный lazy seed.
