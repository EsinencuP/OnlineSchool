# TASK-026 — проектирование до правок

Предметная проекция TASK-024 остаётся источником статуса, причины, подтверждённого остатка и отдельного `temporaryAdmission`. `subjectSubscriptionRows(item: StudentSubjectDto)` сохраняет серверный порядок, точный финансовый `subscriptionId` и различие между нулём, null и отсутствием плана. `SubjectSubscriptions({ items })` в dashboard показывает предпочтительный план по предмету. `SubjectSubscriptionRows({ item, compact? })` в хабе показывает предпочтительный план в списке и все планы в выбранном предмете. `SubscriptionPlanFacts({ plan })` повторно использует факты в деталях. Freshness приходит из существующего QueryState, свежая заморозка показывает ссылки на ранее выданную работу только по серверным capabilities.

`Subscription` сохраняет существующий URL и выделяет `SubscriptionReads({ subscriptionId })` с React key выбора. Три запроса используют префикс `['student', 'subscription-financial', subscriptionId ?? null]` и один финансовый якорь. Ошибка 403 отзывает кэш всей этой группы, остальные ошибки независимы. Финансовые чтения перевыполняются при возврате, явной загрузке и событиях общей политики financial без фонового интервала. К валидному старому deep link применяется серверная scope validation даже если будущего периода ещё нет в списке. Суммы используют действующий `formatMoneyAmount`, даты форматируются по locale и /me.timeZone.

Планируется узкое исправление действующего `StudentSubscriptionLedgerEntryDto`. `balanceBefore` и `balanceAfter` станут nullable строками, когда у опубликованного списания отсутствует конкретный исторический снимок. Порядок, дельты, replay прочих операций, объекты, фильтрация и три GET остаются существующими. Nullable проходит штатный OpenAPI/SDK цикл. Новых DTO, операций, миграций и финансовых команд нет.
