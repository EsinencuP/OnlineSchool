The sole preference remains `packages/ui/src/locale.tsx`: unchanged store, storage fallback and cross-tab subscription. `student-messages.ts` is a statically typed, tree-shakeable dictionary in the existing UI package. Its keys participate in the existing MessageKey/MessageCall interface and placeholder parity. `useStudentLocale` only reads useLocale and selects these messages; it has no state, persistence, event channel or second i18n framework. Staff bundles do not import the student-only text, confirmed by the unchanged staff route budget totals.

The MaterialItemDto extension projects existing `p.educational_subject_id`, `p.can_download`, and `o.file_name IS NULL`. No subject or title is inferred from filenames. Contextless null and missing original filename get localized system labels; a human subject named «Без предмета» or a real filename «Материал» stays unchanged. Old responses without optional metadata keep raw text and use a neutral open action. List filters and total remain server-controlled. Grant ownership, revocation/expiry, signing, FileAuditLog and no-store are unchanged; enrollment alone never issues a file grant. Inline READ is readable bytes, not DRM.

Secret commands use direct closures and the established CSRF transport, not useCommand/React Query mutation variables or serialized reusable intent refs. Only an explicit attempt gets an audit correlation UUID. Password/OTP fields clear after the attempted command; typed input survives ordinary locale changes. Unknown email-request does not claim a sent code or retry. Unknown auth-rotating login/password/email-confirm/logout uses the established verifySessionOutcome boundary to abort leases, clear private caches and hide the old view. A successful confirm resets the local session and bootstraps authoritative /me before profile navigation. Backend policies and staff MFA were not changed.

Private material capabilities live only in the immediate response/local call stack before browser handoff. They are never query/mutation data, React state, refs, storage, application history state or evidence. Fresh authorization is requested per explicit click; invalid HTTPS/expired responses cannot navigate. Logout and second-tab demo switching discard a held late response before navigation. The local browser fixture blocks external traffic; the one successful handoff is an intercepted synthetic download, not S3 acceptance.

UI states checked locally: ready, loading via existing boundary classification, empty, stale, error, pending, unknown, forbidden, limited/suspended and session retirement. New route screenshots include relevant ready/pending/error/unknown/empty/stale/403/limited states. This is not a fresh exhaustive end-to-end execution of every historical lesson/homework/report workflow.

Real PostgreSQL predicates/locks/triggers, S3 issuance/revocation/expiry, OTP delivery and live credential/session cookies remain NOT_RUN. The 200% local check uses a 640×500 CSS viewport with DPR2 (1280×1000 device output), including real responsive media-query reflow, keyboard and reduced motion; it is an emulation, not a physical-device certification. Full recursive regression and TASK-035/FND-GATE remain separate.
