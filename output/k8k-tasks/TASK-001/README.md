# Восстановимая основа TASK-001

Основной снимок:
`snapshots/20261103T194929.397313Z-086d9a29/manifest.json`.
Контрольный повтор:
`snapshots/20261103T194942.294804Z-89ee5620/manifest.json`.
Оба имеют dirty digest
`d716b9262ca859e0048d46b563872d9690026089eb1cb53b28f453555044ee76`.

Работать из `D:/OnlineSchool`. Безопасная повторная проверка создаёт **новый**
каталог восстановления, не меняет исходники или существующие снимки:

```powershell
pnpm k8k:baseline verify output/k8k-tasks/TASK-001/snapshots/20261103T194929.397313Z-086d9a29
```

Результат печатает `recoveryDirectory`; внутри находятся:

- `worktree/`: HEAD-версии dirty tracked-файлов после применения `tracked.patch`;
- `index/`: HEAD-версии после `staged.patch` (в этом снимке он пустой);
- `exact-bytes/`: все170 файлов из `files/` без изменения кодировки/CRLF/binary;
- `verification.json`: результаты и manifest SHA256.

`worktree` и `index` — отдельные новые локальные Git-репозитории только для
проверки patch, не полный checkout приложения и не новая ветка рабочего репозитория.
`core.autocrlf=false` применяется только к командам внутри этих каталогов.

Полное восстановление выполнять только в отдельной рабочей копии HEAD
`171db2142858e035594737e141d422fa5378e844`. Сначала проверить SHA256 manifest и
backup, затем восстановить HEAD→index состояние из `staged.patch`, рабочие изменения
из `tracked.patch`, после чего наложить точные байты `files/` для всех manifest entries.
Удаления при наличии отражаются `exists:false`; в принятом снимке их нет. Применять
patch поверх нынешнего dirty source tree нельзя: эта задача такую операцию не делает.

Для нового снимка использовать `pnpm k8k:baseline capture`. Существующие каталоги
не перезаписываются. Новый снимок включает текущее состояние исходников; output
исключён из untracked backup, поэтому снимок не включает сам себя.

Ограничения:

- HEAD должен оставаться доступным в локальном Git для восстановления чистых файлов;
  отдельный Git bundle/внешний disaster-recovery backup не создавался.
- Manifest содержит пути, размеры, SHA256, tracked/untracked тип, исходный commit и
  `backupPath`; `files/` содержит реальные байты. Метаданные ACL/mtime/NTFS streams
  не сохранялись.
- `.env*`, cookies/session state, ignored-файлы, зависимости и generated outputs
  не читаются/не копируются. Пользовательские RAR/ZIP и untracked исторические outputs
  остаются на исходных местах; полный список исключений — `excludedUntracked`.
- Хеширование двух RAR подтверждает их неизменность, но не заменяет backup архивов.
- Tracked screenshots и `template/newtemp.png` сохранены как binary. Новые screenshots
  не снимались; проверка восстанавливаемости не подтверждает UI/бизнес-приёмку.
- Сканирование credential patterns ограничено; одна точечная оговорка относится к
  фиксированному негативному URL-тесту в `tests/unit/student-dashboard.test.mjs`.
  Реальные аккаунты/провайдеры не использовались, публикации артефактов не было.
- Два ранних незавершённых capture и промежуточные версии оставлены как история;
  принятыми являются два явно названных выше снимка с `verification.json`.
- Снимки созданы до финального обновления журнала, матрицы и implementation status.
  Эти три намеренных изменения отдельно отражаются в `final-verification.json`.
