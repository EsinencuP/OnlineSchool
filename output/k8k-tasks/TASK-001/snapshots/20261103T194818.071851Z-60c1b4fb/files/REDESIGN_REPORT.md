# K8K — результат визуального инкремента

02.11.2026 · ветка `feat/k8k-design` · база `5f3c6f0`.

Общий визуальный слой K8K подключён к ученику, менеджеру, преподавателю, руководителю и оператору. Это **локальный opt-in preview**, не production-релиз и не заявление о завершении всех фаз вложенного плана. API, SDK/OpenAPI, серверные команды, БД, денежные расчёты, CSRF, идемпотентность и обработчики авторизации не изменены.

## Как посмотреть

Добавить `?ui.k8k=1` к адресу кабинета. Для Vite base URL использовать завершающий `/`: `/manager/?ui.k8k=1`, `/student/?ui.k8k=1`. Для staff: `/teacher/?ui.k8k=1`, `/director/?ui.k8k=1`, `/operator/?ui.k8k=1`. Флаг сохраняется в `sessionStorage` текущего origin. `?ui.k8k=0` возвращает прежнее оформление. По умолчанию флаг выключен.

Наличие флага не даёт никаких прав. Серверный допуск и существующие ролевые маршруты сохраняются.

## Изменения

- Единые provisional-токены из раздела 3 дизайн-инструкций: цвета, типографика, радиусы, поверхности, контролы, статусы и фокус. Новый слой изолирован селектором `:root[data-k8k]`.
- Golos Text Variable поставляется локально двумя WOFF2-подмножествами; Lucide используется через общий `K8KIcon`. Бренд и HTML title заменены на K8K Academy.
- У ученика главный модуль — ближайший урок с предметом, временем, преподавателем, существующим серверным `canJoin` и проверкой URL. Отсутствующая ссылка объясняется текстом; закрытый вход — отключённой кнопкой и пояснением. Два быстрых входа — ДЗ и расписание. Уведомления доступны из колокольчика; навыки — качественными статусами, без общей шкалы.
- У менеджера выделяется одна фактическая просроченная задача с переходом к исходному объекту и всей очереди. Поиск сохранён; на телефоне занимает полноценную строку. Показатели на 1024–1499 px размещены в три колонки.
- У преподавателя выделен следующий собственный урок; обзор содержит краткий список ДЗ и переход к полному. Директор сохраняет существующий операционный обзор без новых финансовых KPI. У оператора прямой заголовок «Состояние платформы» и прежний liveness-ответ.
- Мобильная навигация согласована на ширинах до 1024 px. Контролы сохранены, рабочие тексты увеличены, длинные строки переносятся. Локальные метки загрузки показывают время последнего успешного ответа.
- Общий `account-ui` переиспользован вместо второго UI-пакета. Полные формы, маршрутизаторы и обработчики действий сохранены в приложениях.

В синтетические fixtures добавлен ответ уже существующего общего меню аккаунта; рабочий API не менялся.

## Что остаётся открытым

Полная предметная разбивка всех абонементов, личные суммы преподавателя и финансовые KPI директора не выдуманы при отсутствии нужного API; подробности в [аудите](REDESIGN_AUDIT.md). Условный директорский обзор доступен только в opt-in preview.

Токены/шрифт/размеры остаются provisional до VIS-13/14/16; языки и точный executive scope не утверждались заново. Не созданы новые бизнес-функции, полный поведенческий AppShell, Storybook-каталог всех девяти состояний, новые таблицы/календари/BI, .ics, сохранённые фильтры, офлайн или тёмная тема. Общая доступность всего продукта, полный Lighthouse, полный регрессионный gate и production GO не объявляются пройденными.

Legacy CSS и `DashboardLegacy` оставлены до визуальной приёмки; удаление старого кода не выдаётся за выполненное. Push, PR, merge и deployment не выполнялись. Исходные пользовательские архивы, `newtemp.png` и UX-источники сохранены.
